# Image2.5 Prompt — v6 Minimal Framework Figure

## Purpose

Generate a new Figure 1 from scratch for a multi-agent systems paper. The figure
must communicate one idea in five seconds:

**a recipient's use of a peer's artifact becomes evidence that changes the next
peer assignment.**

Use the attached top-conference framework figure only as a visual grammar
reference: one reading direction, one dominant central mechanism, sparse labels,
large whitespace, and a clean paper figure. Do not copy its text, icons, or
layout. Do not use the previous dense figure as a source image; rebuild the
composition from scratch.

## Exact canvas and composition

Create a wide 16:5 landscape figure on a pure white paper background. Use a
single left-to-right reading path with one delayed feedback loop. No page title,
legend, caption, or paragraph inside the image.

Place four visual groups:

1. **Left, orange rounded card**
   Exact title: `DELIVER`
   Exact small labels: `artifact`, `producer → recipient`

2. **Center, the largest object: pale-purple rounded dashed enclosure**
   Exact title: `EARNING ROLES`
   Exact small subtitle: `situated evidence`
   Inside it, place exactly three compact connected nodes in one horizontal row:
   - `USE`
   - `JUDGE`
   - `CREDIT`
   Do not put explanatory sentences inside the nodes. Use only these words.

3. **Upper right, blue rounded card**
   Exact title: `SELECT`
   Exact small label: `local peers`
   Show three small outlined circles labeled exactly `A`, `B`, and `C`.
   Add a tiny blue lock/seal mark with exact label `sealed`.

4. **Lower right, blue rounded card**
   Exact title: `OUTCOME`
   Exact small label: `quality + cost`

## Arrows and labels

Use only four arrows. Make each arrow thick enough to survive two-column
printing, with arrowheads clearly separated from text:

- orange solid arrow `artifact` from DELIVER to USE;
- blue solid arrow `evidence` from CREDIT to SELECT;
- blue dashed downward arrow `after seal` from SELECT to OUTCOME;
- gray dashed upward return arrow `delayed` from OUTCOME back to the SELECT card,
  terminating at the small `sealed`/future-selection area, never at DELIVER or
  the central nodes.

The central row should visually read `USE → JUDGE → CREDIT`. Do not add any other
arrow labels, equations, bullet points, metadata, version strings, or prose.

## Visual language

High-end ICML/NeurIPS/AAMAS framework figure. Flat editorial vector-like style,
precise neutral sans-serif typography, consistent stroke widths, restrained
orange/green/blue/purple/gray palette, subtle rounded corners, generous
whitespace, and strong visual hierarchy. The central EARNING ROLES enclosure
must be visibly dominant. Keep all text horizontal, aligned, and fully inside
its card. Use color plus position plus arrows so the figure remains readable in
grayscale.

## Hard exclusions

No gradients, 3-D effects, shadows, glossy UI, dashboard styling, screenshots,
people, robots, decorative agent icons, logos, watermark, extra modules, dense
text, long sentences, mathematical formulas, invented metrics, SOTA claims,
percentage improvements, or any text not explicitly listed above. Do not repeat
labels. Do not let arrows cross text or card borders. Do not turn the diagram into
a circular workflow; the delayed return must remain a single thin external loop.
