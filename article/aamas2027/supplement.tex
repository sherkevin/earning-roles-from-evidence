\paragraph{Scorer equivalence.}
The official HotpotQA scorer removes punctuation before articles and treats mismatched \texttt{yes}, \texttt{no}, and \texttt{noanswer} responses specially. The historical project function differs. Applying the official answer-F1 function to the stored HotpotQA router outputs changes six rows and yields 0.432275 rather than 0.432403. The small aggregate difference does not justify calling the functions identical. Official-scored paired claims need both method and comparator outputs, consistent raw dataset identifiers, and the official task-specific scorer.

\paragraph{What the hashes establish.}
The local audit manifest hashes the files actually inspected. It does not establish the identity of an unavailable historical runtime snapshot, the absence of development-set reuse, or the completeness of remote model-request logs. These properties need separate provenance checks. Stored confidence intervals are reused as historical statistics and must not be relabeled as new independent replications.

\section{Worked Failure and Control-Flow Contract}

The recorded example asks whether Scott Derrickson and Ed Wood had the same nationality. Both relevant context passages describe the person as American. At the first hop, the frame registers two subtasks, selects retrieval and consistency-check tools, and forwards an intermediate note. At the second hop, it logs \texttt{REJECT\_REROUTE} for the previous contribution, retrieves one memory event, and answers locally. The final answer is \texttt{no}; the stored gold answer is \texttt{yes}. The raw outputs include three usage entries totaling 3,824 tokens.

This is a selected explanatory failure, not an estimate of failure frequency. The corrected runtime contract requires: (i) every audit has an attributed candidate; (ii) accepted evidence is distinguished from a final answer's correctness; (iii) every reroute or resplit outcome produces that transition, or a documented exhausted-budget termination; and (iv) rejected evidence cannot silently increase future competence. A test should inspect executed transitions, not merely the existence of the expected audit string in a trace.

\section{Prospective Experiment Specification}

\paragraph{Primary causal contrast.}
Correct persistent reputation versus frozen reputation, with identical task evidence, prompts, tools, candidate executors, and resource caps. Add worker-shuffled and task-reset reputation as complementary controls. The primary outcome is mean external task utility over independent task streams. Auxiliary measurements are task-conditioned allocation, audit-error rates, concentration of workload, communication, and recovery from a worker change. A state intervention must actually change the routing input; deleting an unused logging field is not an ablation.

\paragraph{Budget grid.}
The initial design uses attempted-call caps of 4, 8, and 16 and separate token caps fixed during development. Report both caps and realized cost. Direct reasoning can spend the same budget on independent candidates and verification. Static teams and learned routers receive the same tool library. Development or offline optimization cost is reported separately from deployment cost for every method.

\paragraph{Seeds and order.}
For the primary claim use at least five independently reset streams, with task order seeds fixed in the manifest before outcomes are inspected. A stream is a full state trajectory. The same task order is used for paired methods within a stream, and state does not cross streams. Use uncertainty over independent streams, or a hierarchical method that respects stream dependence; do not pretend all adaptively connected tasks are independent observations. The number of streams alone is not a power guarantee.

\paragraph{Selection discipline.}
Use training or development tasks to choose task categories, prompts, thresholds, cost weight, update rate, and exploration. Lock one candidate per backbone before running the confirmatory tasks. Reserve one materially stronger backbone and an externally defined non-QA task. Report the full frozen comparison matrix. If a checkpoint or protocol is changed after observing evaluation errors, that evaluation is development evidence and needs a new held-out confirmation.

\paragraph{Falsification.}
Withdraw persistent-organization claims if correct history does not improve over frozen, shuffled, or reset state; withdraw equal-budget superiority if an equally resourced direct agent is competitive; restrict generality if stronger backbones or the second task family do not support it. No test requires every individual task to improve. Per-task oracle selection of the best baseline is an upper-bound diagnostic and must not be confused with the best deployable method chosen on development data.
