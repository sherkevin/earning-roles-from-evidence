# ADR 0037 — 论文主线、证据选择与创新点的不可降级约束

日期：2026-09-27
状态：Accepted
范围：earning-roles 的故事线、方法论、benchmark/baseline 与创新点；后续实验和论文写作均适用

## Context

本项目的目标不是堆叠一个能运行的工程组件，而是形成一篇能够被 AAMAS 审查和复现的研究论文。此前的讨论中，故事线、方法论、benchmark、baseline 和创新点曾在工程困难或单次实验失败后发生漂移。这样会把“当前实现还不够好”误当成“研究问题不成立”，也会使实验无法回答论文真正要证明的问题。

因此需要一个高层决议，作为遇到抉择、证据不足或任务漂移时的统一判断标准。该决议只记录已经共同确认的研究要求；临时实现、未验证的方法候选和实验失败不自动改变它。

## Decision

### 1. 故事线与方法论

论文的故事线与方法论必须同时满足：充分、合理、完备、自洽，并且具有明确创新性。问题切口必须精确、sharp，能够清楚说明研究对象、因果关系、可观测信号、方法作用和评价结果之间的关系。实现上的困难、单次失败、数据不足或当前实验未通过，不能自动把研究问题改写成更弱的问题。

### 2. Benchmark 与 baseline

Benchmark 的选择必须能够充分证明论文要证明的命题，并且优先使用公认、权威、可复现的任务或其严格保持任务语义的扩展。Baseline 必须覆盖与主张直接相关的比较对象，并具有时效性、新颖度或经典性；每个 baseline 都要说明它控制了哪一个变量、为什么是公平比较，以及它不能回答什么问题。只有在任务定义、评分信号、信息可见性、数据划分和停止规则都通过审查后，才可以冻结 benchmark/baseline；工程上方便接入不构成冻结理由。

### 3. 创新点

创新点必须立住，不能因为局部实现问题、一次实验失败或短期结果不理想就被悄然删除或降级。当前已经讨论并保留的核心研究主线是“learning roles from others' situated judgments”：让实际承担后续工作的 agent 对交付结果作出有情境的判断，将可归因的证据用于未来责任/角色分配，并检验它是否改善后续任务质量和总成本。

如果要推翻、删除、替换或实质修改这条主线或其创新点，必须先明确列出：反证是什么、反证针对的是问题定义还是实现、有哪些替代方案、对故事线和评价协议的影响，并与用户完成双重确认；确认后另写新的编号 ADR，旧 ADR 标记为 `Superseded by NNNN`，不得静默改写历史共识。当前实验不支持某个具体算法，只能说明该算法候选或实现版本尚未通过相应证据门。

### 4. 决议的应用

遇到抉择、无法决断、证据相互冲突或出现任务漂移时，先回看本 ADR 以及相关的 Goal、任务报告和更具体的 ADR。每个小任务完成后都要记录：它推进了哪个要求、留下了什么缺口、是否改变了任何已确认的结论。没有用户明确同意，不得以实验失败、数据不准、资源不足或实现代价为理由自动降低 Goal 或本 ADR 的标准。

## Consequences

后续工作必须把“研究主张是否成立”和“当前实现是否合格”分开记录。实验失败仍然需要保存并分析，但只能触发方法修正、测量修正或停止当前路线，不能直接触发创新点降级。Benchmark、baseline 和方法冻结都需要独立证据门；论文草稿可以提前写，但未通过证据门的内容必须明确标为候选或内部草稿，不能写成已证实结论。
