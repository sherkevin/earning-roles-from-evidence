# 0002 — Do not promote acquisition probe v1

Status: Applied from the prospectively frozen rule, 2026-09-22.
Authority: decision 0001 and the fixed acquisition v1 development contract.
This is an empirical execution decision, not a new user-endorsed method lock.

## Context

The first real experiment tested whether source-linked procedural summaries
from six native training trajectories improve six independent sibling tasks.
The intended paper needs useful learned changes before qualifying downstream
collaboration. Successful trajectory storage alone cannot establish this.

The original contract required at least two paired task-success wins, no losses,
nondecreasing assertion coverage, unchanged-package stability and valid
infrastructure before its conditional development comparison.

## Decision

Do not enter that contract's twelve conditional dev episodes and do not promote
this acquired package as evidence supporting Q1. Preserve the exact package,
all outcomes, original errors, the declared acquisition retry and full costs.
Do not retrospectively substitute efficiency or verification frequency for the
predeclared success endpoint.

## Rationale

Both arms achieved 6/6 final official successes, producing zero paired wins.
One treatment pair also contains an unwaived empty-text HTTP200 response.
These independently fail the gate. A separate scorer-path defect was repaired
from byte-identical saved state without a new model call; it is fully recorded.

Treatment used 99 versus 96 attempted calls and 19.9% more known context tokens.
Acquisition and induction additionally consumed 102 calls. Output tokens fell,
so a uniform improvement across resources cannot be claimed. A label-masked
audit found many summarized procedures already present in both arms.

## Consequences

- This package is an archived development candidate, not a validated skill.
- The larger Q1 hypothesis remains unsupported, not universally disproved.
- Small training-sibling ceilings cannot determine full-dev headroom.
- A separate environment diagnostic cannot retroactively pass this gate.
- Reuse the adapter, native runtime, source-linked traces and accounting.
- Any different learner or primary endpoint needs a separate prospective
  scientific question and contract; failed tasks cannot become a favorable
  replacement evaluation population.
