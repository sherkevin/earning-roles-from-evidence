# ADR 0045 — Chain-local judgment and path lineage

- **状态**：Accepted
- **日期**：2026-10-05
- **范围**：ArtifactRole 主轨的责任表示与选择目标
- **取代**：无；细化 0019、0022、0043，不改变其证据门

## 背景

协作任务不是一次独立的打分，而是沿着派发、交付、接收和下游使用形成一条链。若把最终结果直接反推给最早的 Agent，会混淆中间 Agent 的使用行为、环境失败和原始交付质量。更清晰的基本单位是“一次有明确发送者和接收者的交接”。

## 决议

1. 每次交接都表示为一条有向边：
   `sender -> receiver`，并绑定任务、候选版本、artifact digest、时间和信息快照。
2. 接收者对发送者交付结果的验收是**边上的局部 judgment**。它回答的是“在本次使用条件下，这个发送者的交付是否满足契约”，而不是无条件地评价发送者的全部能力。
3. 多条边通过 artifact lineage 和 task lineage 组成路径。只有当中间交付被实际采用、后续结果可重放且责任边界完整时，才允许把 later outcome 归因到路径中的具体边；缺失、混合责任或环境不可观测时保持 `UNKNOWN`。
4. 路径分数不得未经定义地把各边分数相加或相乘。论文需要明确一种可审计的 path-credit 规则，并与 edge-local score 分开报告；在该规则实现前，不声称已经完成一般路径聚合。
5. 未来选择的目标是当前任务条件下候选 Agent 的预期下游效用，至少包含接收者验收质量，并在实验中加入最终质量、风险和成本。局部 judgment 是可延迟到达的学习信号，不等同于最终效用本身。

## 当前实现边界

现有代码已经记录发送者、接收者、版本、证据、assignment 和 delayed selected-only update，并能阻止 UNKNOWN/乱序事件更新策略。当前 `contextual_trust_linear` 只用固定特征和在线 RLS 学习一个候选信任代理；它尚未实现任意长度路径的最终聚合，也没有证明该代理能提高闭环任务效用。RARE 仍是待验证候选机制。

## 后果与验收

- 实验必须同时报告 edge judgment、path-level later outcome、责任归因覆盖率、UNKNOWN 分母和完整成本。
- 每个被选 Agent 的比较必须使用同一任务上下文、候选菜单、propensity 和可见历史；不能用最终结果泄漏到选择时点。
- 在增加 path-credit 实现前，继续把“链路记录正确”和“选择效果提高”作为两个独立验收项。
