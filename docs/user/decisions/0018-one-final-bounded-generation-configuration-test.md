## 背景

N02 v1 首次 producer 请求120秒无响应，v2首次请求在300秒持续生成thinking后
仍无最终text；均为UNKNOWN，两次episode尝试已用。原“连续两次UNKNOWN停止”
及v2“不再恢复”已经触发，本次不能伪装成原卡允许的续跑。

v2记录约1.18秒即开始返回HTTP200数据，之后3149个thinking_delta、47668字符、
没有最终源码。这说明该次失败是当前生成配置未在时限内完成，而非连接没建立。
两个短默认请求正常；一个显式 `thinking: {type: disabled}` 的短请求也正常且无
thinking事件。短请求不证明完整任务可完成，恰好留下一个可证伪的配置问题。

## 修订

允许**一次最终的、显式关闭thinking的完整生产请求**，算第3个episode尝试。
只在这第3个episode从交付到判断/消费/终局全部合法完成后，才执行第4个预定实例，
验证他人证据驱动的后续派工。合法FAIL也可继续，不以高分为继续条件。

此决议明确取代v2卡的“不再恢复”和跨版3次上限；跨版绝对上限仍为最初N02的4次。
旧卡和旧UNKNOWN保持不变，不把失败计数清零。此次不是单纯运输修复，thinking
属于agent配置，故新结果不得与v1/v2合并成同条件重复样本。

任务、提示、模型、输出请求cap、300秒上限、评分、动作权限与更新不变。
不再增加health、token、超时，不换prompt或model形成v4。
任何一步出现thinking、截断、无有效输出、UNKNOWN、协议无效或泄漏即关闭本路线。
关闭后保留可复用契约/隔离/评分/账本，另行论证一个替代执行设计，不能悄悄补样本。
