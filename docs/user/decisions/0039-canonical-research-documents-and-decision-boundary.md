# ADR 0039 — 研究主文档与决议文件的职责边界

日期：2026-09-28
状态：Accepted
范围：earning-roles 的故事线、方法、benchmark/baseline、评价标准、研究报告和决议文件

## Context

项目中的研究内容分散在主线稿、方法候选、benchmark 审查、评价规则和任务报告中。
如果没有唯一生效版本，同一个概念会在不同文件中被重复定义，临时实现细节也可能被
误读为研究结论。0038 已规定决议需要双重确认；本决议进一步规定不同文档各自负责
什么，避免用决议文件替代正式研究文档。

## Decision

### 1. 六份唯一生效的研究文档

当前研究只维护六类 active 文档，每类同时最多一个生效版本：

1. 故事线与创新点；
2. 方法论；
3. benchmark 与 baseline 及实验计划；
4. 故事线评价标准；
5. 方法论评价标准；
6. benchmark/baseline 评价标准。

六份文档的当前版本登记在 [`docs/research/canonical/README.md`](../../research/canonical/README.md)。
版本文件放在 `docs/research/versions/`，旧版本不得删除；active 文件必须标明版本、
状态和 supersedes 关系。研究报告、实验日志和任务报告是证据或进展记录，不得另行
宣称为 active 故事线、方法或 benchmark 定义。

### 2. 各文档的职责

- 故事线文档定义研究对象、问题切口、因果链、创新主张和明确的非主张。
- 方法论文档定义数学对象、输入输出、更新流程、实现约束、候选机制和待决事项。
- benchmark/baseline 文档定义任务资格、数据划分、评分、对照、指标、实验顺序和停止规则。
- 三份评价标准文档分别规定审查前三类文档时必须满足的质量条件；它们不替代研究内容。
- 决议文件只保存一个小的、已经对齐的关键选择、争议解决或不可变约束，例如模块边界、
  label 语义、停止规则或某个实现取舍。决议文件不复制六份研究文档的全文，也不承载
  每次实验的进展。
- 任务报告记录完成了什么、证据在哪里、哪些仍开放以及下一步；实验原始日志只保存
  可复现执行证据。

### 3. 版本和变更规则

研究含义的变更（故事、方法、benchmark/baseline、评价标准或 Goal）必须先经过用户与助手
双重确认。确认后，正式研究文档用新的版本文件并更新 active 指针；只有当变更本身是一个
独立的小取舍、边界或不可变约束时，才另建一份 ADR。未确认的建议写入候选研究报告或任务
报告，不得直接覆盖 active 版本。某一类文档只能有一个 active 版本，但可以有任意多个
archived/superseded 版本。

如果变更只是修正链接、拼写或机器生成索引，不改变研究含义，可以原地修复并在任务
报告中记录。实验进展和证据更新进入 task report/log，不为了每次进展重复建立 ADR。

## Consequences

从本决议开始，所有研究判断先定位到六份 active 文档之一；工程细节留在代码、runbook
或任务报告；争议性小决定才进入 ADR。这样能让论文主线、方法和实验设计只有一个当前
来源，同时保留完整的历史和失败证据。该决议不冻结当前 RARE、PIPE3 或任何 backbone；
它只规定信息应当放在哪里以及如何变更。
