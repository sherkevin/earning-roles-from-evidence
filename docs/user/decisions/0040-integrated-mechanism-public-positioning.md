# ADR 0040 — 组合机制的对外创新定位与内部验证

日期：2026-09-28
状态：Accepted
范围：earning-roles 的故事线、创新叙事、机制消融和论文写作

## Context

当前方案由 situated judgment、责任过滤、延迟更新和 future assignment 等部分组成。
内部审查必须识别哪些部分来自已有方法、哪些交互真正产生了新性质；但如果在论文正文中主动写成“这些组合不是创新”，会把尚未完成的内部审计误写成论文定位，并削弱一个可能成立的整体机制。

旧的故事线文本使用了“创新不在把现成组件拼接起来”的否定式表述。该表述适合作为内部审计提醒，不适合作为最终论文的公开叙事。

## Decision

1. 论文对外把这些部分写成一个有机的整体机制：它解决一个明确的信息、责任和时序限制，并产生可检验的系统性质。
2. 正文不主动罗列“哪些组件不算创新”，也不把贡献拆成若干互相独立的工程模块。
3. 内部仍必须验证整体机制不是措辞包装。使用 matched composition baseline、留一模块消融、预先指定的交互效应和跨 root 复现。
4. 组合机制的创新证据至少包括：
   - 完整机制相对最强同信息 baseline 的质量—成本增量；
   - 每个必要模块移除后的机制性质损失；
   - 关键模块对的非加性交互；
   - 四段闭环箭头均有独立证据；
   - 不能由 contextual trust/bandit、raw acceptance 或 pooled controller 解释全部收益。
5. 若整体机制没有产生这些系统性质，内部报告应记录为组合未形成可识别增量，并修正机制；在用户和助手确认前，不静默删除主线或把失败改写成目标降级。

## Consequences

- 当前故事线升级为 v1.1，新增有机整体创新判定和量化审计定义。
- 内部审计与论文正文的语言职责分开：审计可以尖锐否定，正文只陈述被证据支持的整体机制。
- 后续 baseline 和 ablation 不再只比较单个组件，而要包含最强的已有组件组合。
- 该 ADR 不证明创新已经成立；它规定如何把“组合是否形成创新”转化为可证伪的实验问题。
