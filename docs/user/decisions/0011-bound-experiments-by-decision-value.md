# 0011 — 按决策价值控制实验节奏

Status: Accepted process constraint. Date: 2026-09-24.

## 背景

用户要求控制节奏，不做无谓实验，详细分析结果并记录问题，供后续优化。
当前 Stream-JEV 只有合成环境中的在线小头验证和一次 A800 运行时探针。
它们不足以证明真实任务收益、旧能力保留或新训练方法的价值。
增加实验数量不能替代解释现有结果和修正实验设计。

## 决定

1. 每次新实验先写一张短卡：要解决的问题、假设、最小对照、固定样本/seed、
   主指标、资源上限、停止条件，以及不同结果会改变哪个决定。
2. 优先分析已有原始数据和检查实现；能用已有证据回答的，不重跑模型。
3. 一轮只检验一个关键机制。先完成分析，再决定下一轮；不同时开多个方法搜索。
4. 先用小规模闭环排除接入和标签问题，通过后才安排有信息价值的效果比较。
5. 实验结论必须区分：实现正确、运行速度、模拟反馈收益、真实任务收益、
   旧能力保留、创新性。某一层通过不自动意味着下一层通过。
6. 每个问题记录证据、影响、根因或待验证解释、最小修复、验收条件和状态。
   未找到原因时写“未知”，不能以增加样本掩盖设计缺陷。
7. 阴性结果、无效结果和失败保留；修订使用新 ID，不覆盖已有结果或挑好 seed。
8. 实验后明确选择继续、修改或淘汰；没有可能改变的决定，就不安排该实验。

## 本阶段的执行次序

- 先对现有 12-seed 结果做只读复盘和独立代码审查。
- 先修正 residual 目标语义、复杂度和证据表述，再接非零静态模型分数。
- 真实数据第一步只核对输入、候选、标签来源、split 和 delayed feedback 合约。
- 下一次训练前冻结有上限的实验卡；不因 A800 可用就增加训练规模。

## 理由

研究需要减少关键不确定性。一个暴露根本缺陷的小实验，比十次重复的吞吐探针有价值。
结果必须能回到“为什么选择更好、更新更快、旧任务更稳”三个问题。
RLS 是已知在线学习基线；本决议不把它升级为最终论文创新，也不取消原来的研究目标。

## 后果

- 任务状态统一记在 `docs/coordination/AAMAS_TASKS.md`，详细复盘留在相应实验报告。
- 下一轮优先级由未关闭问题决定，不按 GPU 利用率或实验次数决定。
- 本轮只做后处理和文档修正；没有新 LLM 请求、模型训练或 A800 作业。
- 不把本次“可以”解释成 Task36/38 已通过数据资格核查。
- 保留既有研究方向 ADR 0010；具体训练方法仍待证据支持。
