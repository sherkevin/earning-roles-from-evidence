# 0019：判断不直接等同于生产者缺陷或终局质量

日期：2026-09-26。
状态：执行测量约束；落实已接受的真实证据与归因要求，不是最终算法冻结。
适用：后续开发设计；不修改已冻结N02判断、分数或调用记录。

## 背景

N02两次消费者都声明repair，但仅改变其本就负责的consumer.py。
生产者被明确分配queue.py和priority.py，第一轮消费者却将自己的写权限误当
生产者漏做的任务。另一方面，消费四项全通过没有覆盖priority的真实错误。
直接以use/repair/redo映射生产者质量，会同时误计正常集成和漏掉实际缺陷。

## 决定

公开材料必须显式保存原始生产者、消费者和只读支持文件归属。
扩大的repair权限不转移任务责任，也不能把未完成的消费者文件当producer缺陷。

后续记录严格分开四个观察：

1. 消费者封存的判断、信心与具体依据；这是意见，允许错误。
2. 实际源码修改与采用记录；这是行为，不自动证明缺陷的原因。
3. 未经消费者修改的生产者交付检查；只支持所覆盖的公开义务。
4. 最终消费者产物检查及总成本；这是团队结果，不回填为原producer正确性。

正常集成成本、上游修改阶段成本仅在独立可测时分别记录。
同一次consumer调用同时做二者时，分解值为null，只报告实测调用总成本；不按
修改行数分摊，也不为易计费强制拆成额外模型调用。全程成本仍完整保留。
未有合法对照时，任何阶段耗时均不命名为已识别的“额外返工成本”。
UNKNOWN保留为缺失/未确定，不为方便训练强制改成0。

## 理由

目标是判断的增量价值；如果把判断直接当ground truth，再优化接受率，
高分无法证明团队变好。职责归属和独立结果先分清，才有可解释的学习目标。

必须同时区分“交付合同要求”和“实际下游使用依赖”。priority的检查能覆盖
交付义务，但当前consumer并不使用priority；不能把它的正确率称为消费收益。

## 后果

旧use=1、repair=0.5、redo=0保留为N02接线映射及raw-acceptance比较思路，
不再作为新peer-role实验的默认正确性标签或已验证的效用函数。
新的目标、反馈可见性及标量化规则必须在新卡中前瞻冻结，不看结果调权。

材料契约升为v3；冻结运行使用各自source_snapshot，禁止用当前代码改写历史。
此决议不替换ADR0013的最小概念边界，不选择benchmark、backbone或updater。
持久经验的具体实现仍为待审设计。
