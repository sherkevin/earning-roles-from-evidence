# Q1 与方法干净度自审

2026-09-23。作者侧方法审查；三份独立只读意见分别检查概念、实验识别和相关工作。本文件记录**尚未解决的问题和候选取舍**，不是新 Q1、已冻结算法、实验方案或外部审稿结论。本次没有新增模型调用。

## 判断

撤回上一轮口头提出的“私有能力 → 下游贡献证据 → 角色绑定 → 子工作流组合 → 未见组合优于共享程序库”作为**待锁的方法**。它是一份研究愿景，不是一种单一可执行的干净方法。现行 [Q1 v6.1](AAMAS_Q1_worker_differences.md) 也尚未锁定：其资格规则、测试选择、版本采纳和迁移假设仍有独立缺口。两者不能靠改写标题或补上数学符号变成已经成立的创新。

这里的“干净”最低标准是：一个明确的决策、一个明确可观测的学习信号、一个冻结的其余执行环境、一条可被强简单方法推翻的机制主张。相同模型、相同预算、未见任务和官方评分属于**评价条件**，不是方法步骤或创新点。

| 视角 | 上一轮工作的具体问题 | 对论文的后果 |
|---|---|---|
| 问题定义 | 一句话同时要求学到能力、归因贡献、分配角色、组合流程和跨组合迁移；没有指出唯一要学习的决策 | 正结果也回答不了“哪个机制有效” |
| 因果识别 | 终局成功受任务难度、前驱输入、消费者、状态和预算共同影响；一次被验收不能直接算某个 agent 的边际贡献 | “凭贡献挣得角色”缺少与相同状态下替换执行者的配对测量 |
| 算法 | 同时可修改技能、交接、图、绑定和记忆；没有唯一的新算子、合法反馈边界及精确更新规则 | 实现会变成可调系统，消融难以隔离贡献 |
| 理论 / 对照 | 若集中控制器拥有完全相同的信息、状态和不受限的策略类，它可以模拟任意证据到绑定的映射；“本质优于集中式”不成立 | 只能在明确有限上下文、局部信息、通信或计算预算下讨论归纳偏置/实用收益；强对照应放在实验，不写入 Q1 的结论 |
| 先例 | [AAMAS 2012 的协同学习](https://www.ifaamas.org/Proceedings/aamas2012/papers/5B_4.pdf)、[SkillMAS](https://arxiv.org/abs/2605.09341)、[SERO](https://arxiv.org/abs/2605.28433)、[AgentNet](https://papers.nips.cc/paper_files/paper/2025/hash/9a379c1b05793d1c42dc832269834515-Abstract-Conference.html) 已覆盖贡献、分工或组织演化的关键组合；两个不同的 [SkillComposer：技能进化](https://arxiv.org/abs/2606.06079) 与 [技能序列组合](https://arxiv.org/abs/2606.32025) 又限制了泛泛的技能复用主张 | “把几个好模块放在一起”不是已找到的创新；还需要一个与近邻可区分的新估计量、决策条件、信息约束或可靠实证发现 |
| 实验与叙事 | [R0](../../../artifacts/experiments/aamas2027/dev_20260922/report.md) 是单代理六卡注入，官方 6/6 对 6/6，未证明专长；[R2](../../../artifacts/experiments/aamas2027/handoff_effect_20260922/native_summary.json) 是研究者指定边界后的程序因子回放；[R3](../../../artifacts/experiments/aamas2027/program_control_20260923/summary.json) 的同源普通程序在三个同家族实例上复现其最佳结果；AppWorld 当前没有原生多代理角色边界 | 这些是真实而有用的诊断，不是自然分工、在线学习或独特协调机制的正证据；继续加模块会重演 [EMNLP 评审](../../../EMNLP2026-OpenReview-审稿意见汇总.md) 指出的难懂、成本和对照问题 |

也有值得保留的资产：原始问题关心的是**真实交付对未来职责的影响**，而非角色提示词；项目已有真实 API、原生评分、原始调用和成本日志，R3 还给出了必须打败的普通程序解释。它们可以支撑下一轮严谨筛查，但不能替代方法创新。

我还忽略了现有 [AAMAS 主稿](../../../article/aamas2027/main.tex)：它在引言中已经把问题收成“什么时候一次验收足以赋予未来职责”，并将任务记忆和分配记录分开。这个研究对象比我上一轮的句子更干净。不过其中的指数滑动平均验收率加成本选择只是一个可执行的**普通基线**，主稿自己也要求与上下文 bandit 比较；不能把回到这套公式等同于解决创新问题。历史 QA 路由实验没有执行该持久更新。

## 两条不能混在一篇 Q1 中的干净路线

| 路线 | 固定什么 | 只学习什么 | 科学问题 / 强反例 |
|---|---|---|---|
| **局部委派与角色形成**（更接近[原始构想](../../../idea.md)） | 初始模型与工具、任务拆分规则、稀疏通信图、技能形成规则和预算；允许真实私有经历造成能力差异，但暂不把技能生成算法算作贡献 | 每个委派者依据自己可见的交付/验收历史，决定自己做或交给哪个邻居 | 局部反馈能否比同信息的上下文 bandit、信誉/匹配规则更可靠地决定后续委派？若反馈与真实价值无关、能力无差异、标准 bandit 等效，就没有新增组织方法。工作流可先作为实际执行轨迹保存；子工作流组合暂不另设学习器 |
| **更新后的交接资格**（现行 v6.1 的收缩版） | 真实取得的旧/新执行包、任务图、伙伴与接口 | 用有限下游测试决定是否替换旧执行包；版本和回退只是决策动作 | 能否在自然出现的更新 × 伙伴失配下，以低于逐对完整回放的成本预测安全替换？若共同接口或同源普通程序足够、资格测试不能迁移，就关闭该假设。它是接口测试论文，而非自动涌现分工论文 |

**我的暂时倾向**：若本篇的不可退让目标仍是“无中央调度，凭局部互动挣得职责”，优先研究第一条；原有的私有能力与工作流都保留为被观察的系统状态，但本篇主方法只改一个委派决策。不能因此称局部信誉更新已新颖：它必须提出与普通 bandit/匹配器有区别且能运行的证据处理规则。若作者允许中心化、重心是已有 AppWorld 资产和短期可测性，第二条更容易做有限筛查，却更难支撑原题与近邻差异。两条现在都**没有可锁的算法**。

## 作者纠偏：被我漏掉的 `learning roles from others' judgment`

作者随后指出，上述“只改委派决策”的收缩仍遗漏了原始核心。[决议 0005](../../user/decisions/0005-retain-peer-judged-role-learning.md)记录已对齐的研究约束：角色应从**实际接收者对交付物的判断**形成，而不只是委派者私下维护一张二元验收率表。原始 [idea.md](../../../idea.md) 的 `a → b → c` 让 `b` 判断 `c`、`a` 判断 `b`；验收、返工、实际推进和终局纠错共同留下对被评价者的职责证据。`P_v`（被评价者的角色证据）与 `B_u(v)`（某个委派者对它的局部信念）是不同对象。前者的聚合和传播方式尚未确定，不能假装已有算法。

因此，上面“局部委派”路线需要再收一层：**先固定技能形成、任务图、接口与下游路由器，只研究如何把有来源、带消费者语境的判断事件转成可校准的角色证据；再看它是否改变后续委派。** 一个更忠于原意的工作问题是：“实际消费者的使用、验收和返工判断，在何种校准条件下能成为执行者承担后续职责的可靠证据？”这只是问题，不是已找到的更新算子或原创性结论。旧主稿的二元 `A∈{0,1}` 指数平均仅可作简单对照；其历史 QA 结果没有执行跨任务持久角色学习。

近邻比前一段所述更直接：[CADMAS-CTX](https://arxiv.org/html/2604.17950v1) 已有局部、任务语境化的同伴能力后验和风险感知委派，但其 §3.6 的反馈是固定 judge/任务 verifier 的二元结果；[RepuNet](https://arxiv.org/html/2505.05029) 有同伴信誉和网络演化；[AAMAS 2008 的任务型信任工作](https://www.ifaamas.org/Proceedings/aamas2008/proceedings/mainTrackPapers.htm) 已研究按以往互动选择帮手。消费者实际使用/返工及逐跳误判校正**可能**形成更窄区别，但经典信任研究和 [Meta-Team](https://arxiv.org/html/2605.29790v1) 的协作者反馈仍是威胁。必须用同信息的上下文信誉/bandit、终局-only、自评和打乱判断来源等对照实测；不能只换一个“社会性”术语。

R0–R3 没有测上述判断到角色的闭环；特别是 R3 对普通程序的局部解释并不构成对这一未实施机制的否证。下一步的首要问题因此是判断事件、被评价者状态、评判者误差与终局校正如何操作化，而不是先决定去中心化是否必须或继续优化交接程序。

## 下一步真正要关的门

1. 按决议 0005 保留“由实际合作者的判断学习角色”为主研究对象，先明确谁能判断谁、判断何物、判断如何影响被评价者的角色证据；去中心化是否为硬约束是后续设计问题。在完成操作化前不把任一路线写回正式 Q1/REQUIREMENTS，不启动新确认实验。
2. 选定后只写一个输入—决策—反馈—更新—输出闭环；逐项列出冻结的模块与唯一可改变的状态。技能获取或工作流组合若也要声明为贡献，必须成为单独的研究问题及独立干预，不能在主问题里顺手加入。
3. 开发阶段先检验必要现象：真实经历是否造成可辨识且非手工制造的能力差异；是否有真实相互依赖、独立决策的多代理交接；合法下游反馈能否预测被替换执行者的边际价值。配对交换只用于离线科学测量，不伪称部署免费看到反事实。AppWorld 的单代理代码分段不满足第二项。
4. 冻结一个强的同信息简单对照和完整成本口径，再运行小批量真实 API 开发实验。实验单位是独立经历配置 × 未见任务组合/家族 × 种子，不是 API 请求数或同家族回放数。若必要现象或机制增量缺席，明确收缩或停止该主张，不能通过加检查器、调弱消费者或挑有利任务挽救。

原有 [G0–G7 台账](../../coordination/AAMAS_TASKS.md)仍是唯一执行台账；本审查为 G0 的问题澄清，不创建第二份任务清单。既有实验的原始日志、失败和预算保持原样。

## 2026-09-23 后续作者纠偏：共同演化才是研究对象

[决议 0006](../../user/decisions/0006-study-peer-judged-role-formation.md)明确撤回上表的“更新后交接资格”作为本篇主问题。工作流中的 agent 与工作流本身通过合作共同形成；把独立更新的 agent 插回旧工作流、再研究能否低成本验收，切错了本篇要解释的自然过程。它仍可能是别的问题，但不能继续设为本篇 G0 的候选主线或 B-gate。

对上文“固定”的准确修正是：不同实验组共用**初始条件、任务机会、非目标更新规则、反馈权限和预算**，但运行中形成的 agent 技能/记忆和工作流状态允许随各组策略共同演化。短时克隆快照只用于判断事件或角色记录的诊断；主效用需在长期完整策略流里检验。上文“被替换执行者”与旧/新执行包失配等说法属于已退役路线，不是当前必需现象。

当前核心仍未被算法和实验锁定：真实接收者的使用、验收与返工如何成为有来源、可纠错的执行者角色证据，并改变其后续职责；在相同信息和总成本下，它能否比任务型信任、普通验收率或强 pooled controller 做得更好。R0–R3 对此没有直接检验。
