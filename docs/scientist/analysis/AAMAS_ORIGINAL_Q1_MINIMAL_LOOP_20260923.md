# 原 Q1 的最小闭环：交付、同伴判断与后续职责（草案）

2026-09-23。**独立方法审查草案；未获作者确认，不是锁定算法、预注册或实验结果。本文件没有调用 LLM API。** 后续[独立审查](AAMAS_ORIGINAL_Q1_NEXT_EXPERIMENT_AUDIT_20260923.md)指出本页的四环设计不能区分可传播的被评者角色证据与 owner 私有信任，也预设了生产/接收席位；因此下文的 288 次调用估计仅是废止的草案预算，**不得按本页直接执行或声称验证角色形成**。研究方向以[决议 0006](../../user/decisions/0006-study-peer-judged-role-formation.md)和[正式要求](../../paper/aamas2027/REQUIREMENTS.md)为准：agent 与 workflow 在合作中共同变化；固定 workflow 的人员替换不是 Q1。

## 一个可反驳的 Q1

在初始使用相同模型、提示、工具与空记忆，之后只凭合法的局部经历持续变化的 agent 群体中，**真实接收者对交付的行动前判断、实际采用/返工及其公开后果**，能否成为被评 agent 的角色证据，使后续局部责任选择在相同信息、存储和总调用预算下，比情境信任或 Meta-Team L2 式同伴画像获得更好的独立任务质量—总成本？这里检验的是判断到职责的因果链；不把 agent–workflow 共生本身或 Beta 更新改名当创新。私有能力和 workflow 可按各组共同声明的规则演化，短程克隆只诊断机制，不代表完整共演。

必须分别识别三个量：①展示交付相对于隐藏交付，对**同一接收者**完成该任务的质量、复核与总成本的边际影响；②同伴事件对该生产者**未来独立、经盲审交付质量**的预测价值；③读取这些事件后改变职责，相对于同信息强选择器对后续官方质量和总成本的增量。验收声明、行为匹配、官方终局分数各自不能替代另两个量。[v4→v5 的唯一完整开发案例](../../../artifacts/experiments/aamas2027/peer_judgment_resume_v5_20260923/report.md)恰好显示接收者独立核查后执行匹配请求，终局失败却仅来自接收者完成回报格式，同时生产者来源引用不全；它未证明交付的边际贡献或角色形成。

## 门 0：先看交付是否真的帮到接收者

可先把已封存的 `3c13f5a_3` v4 提案当作**选中后的开发材料**，在两个全新、同任务 ID/种子/初始公开世界哈希的 recipient 世界运行：一边显示原提案，一边隐藏；模型路由、合法工具、基础提示、审阅/行动上限相同，随机固定运行顺序。两边在任何写动作前封存待执行计划；可见边另封存对提案的 `accept/repair/reject/unknown` 和拟使用行，隐藏边的这些字段为 `not_applicable`。两边分别封存实际查证、写操作、返工及完成回报；两个行动日志封存后才运行私有离线 scorer。提案的 7 次历史生产者响应及生产者工具成本仍计入“有交付”路径；只看 recipient 调用数会偏袒该路径。隐藏边若只获得较少总计算量，则同时报告质量—成本原始二元结果与等总预算的敏感性对照，不能称它是预算匹配的角色方法比较。相同 seed/温度 0 不保证 provider 输出完全可重现，单例也不能估计总体因果效应。

要决定 AppWorld 是否值得当主实验基底，应在**运行前**另选至少三个不同任务家族的公开开发 ID，重复可见/隐藏的配对诊断，保留完整失败和生产者成本。若三个预选家族中 recipient-only 均达到不低于有交付的官方质量、消耗不高于完整有交付路径，并重做所有关键公开查证，则停止把 AppWorld 人工“只读生产者→可读写接收者”拆分当作主科学证据；这只否定该实验基底，不否定原 Q1。若有正负混合，也不能从中挑一个成功题宣布交付必需。AppWorld 原生是一位自主 agent 的 API 任务，[基准与本地适配审查](../../../references/aamas/native_collab_benchmark_20260923/README.md)已说明该拆分由我们添加。

## 门 1：最小、但仍只是开发性的角色闭环

先修好通用交付来源与有界公开观察：A0 v3 四例 [0/4 完整链](../../../artifacts/experiments/aamas2027/peer_judgment_a0_v3_20260923/report.md)，v4 因传输 UNKNOWN 按规则停在两例 [0/2 完整链](../../../artifacts/experiments/aamas2027/peer_judgment_a0_v4_20260923/report.md)，其中一个请求达 553,677 JSON bytes。无 LLM 原生权限 fixture、一次独立真实 provider 健康调用、请求大小/分页回执上界和一个预选新 ID 的完整链烟测通过前，不应预约下表的长期调用。超时和被删失的例子是 UNKNOWN，不是评判差或方法失败。

四个持久身份从同一模型、提示、工具权限和空状态开始，暂按四环 `A—B—C—D—A` 排班。`A/C` 是两个将来可选的交付者，`B/D` 是他们的两个真实接收/行动者；这些是小实验中的临时暴露安排，不是预置能力或论文所称全部角色已涌现。每个身份有隔离的合法私有历史。每个环境任务使用独立重置世界，生产者只读，接收者写前独立审阅；控制器仅排班、隔离权限、记录和离线评分，不利用私有答案委派。

| 阶段 | ID/世界数 | 预先固定的配对 | 能回答什么 |
|---|---:|---|---|
| 训练情境 1 的 ID `x1,x2` | 2 个 ID、4 次执行 | `x1: A→B,C→D`；`x2: A→D,C→B`，每条在不同重置世界 | 同一情境中，两候选各被两位实际接收者判断一次；顺序和 ID/身份映射预冻结 |
| 训练情境 2 的 ID `y1,y2` | 2 个 ID、4 次执行 | `y1: A→D,C→B`；`y2: A→B,C→D` | 交叉情境，降低简单的生产者、接收者、任务难度主效应混淆 |
| 未来情境 1、2 的 ID `x3,y3` | 2 个 ID、4 次执行 | 本地 owner `B` 或 `D` 在读任何未来结果前从 `A/C` 中选一；再由同一训练后检查点克隆世界分别运行 `A/C` | 两个未来机会上的影子选择和配对候选后果；克隆分支不能同时写回 live 历史 |

这恰是**8 次训练交付—接收执行 + 4 次未来候选执行**，不是 12 个独立任务。若 `x1/x2/x3` 和 `y1/y2/y3` 是 AppWorld 每家族 `_1/_2/_3`，只有**两个相关场景家族、六个相关 native ID**；它们的 train 来源和部分 scorer 已被研究侧接触，全部只能作开发诊断，不能算未见确认集、稳定 judge 校准或总体胜率。交叉排班不能消除任务×接收者交互。未来确认必须按真正独立的来源任务/家族分组，先锁协议再看结果；短程安排还不能证明四个 agent 在完整图上自动形成组织。若换 CooperBench，官方[代码](https://github.com/cooperbench/CooperBench)与[数据卡](https://huggingface.co/datasets/CooperBench/cooperbench-dataset/blob/main/README.md)提供有冲突的双 feature 合作与测试，但公开的 652 是 feature **pairs**，复用 199 features 和约 30 个 PR task 根；划分与不确定性须按 PR/仓库聚类。它原有 feature seat 指派，若加入下游整合者及自适应选人，也是明确的新适配，不是开箱即用的角色基准。

## 必需事件和信息边界

每行 JSONL 的公共字段为 `timestamp,event_id,stream_id,episode_id,native_id,family,actor_id,world_id,config_sha,runner_sha,event_type,payload`；任意模型尝试另有 `request_sha,model_route,returned_model,elapsed_ms,prompt_tokens,completion_tokens,cache_tokens,error,usage_known,budget_before,budget_after`。原始模型输入/响应、合法工具输入/响应和脱敏审计保留在独立原始文件；密钥不入日志。所有事件有单调序号，`UNKNOWN` 含明确删失原因，不能转为拒绝或零成本。

按下列顺序封存并拒绝事后修改：

1. `episode_open`：任务、公开初始状态哈希、排班、邻接、权限、身份的私有记忆/role/workflow 版本、预算预留；`world_io` 和 `llm_attempt` 逐调用记录 actor、工具、输入/输出哈希、只读/写权限和成本。
2. `delivery_sealed`：生产者 ID、交付哈希、逐行动主张与 typed public `source_refs`、引用对应的世界/字段/值、覆盖及不确定性。目录列表或任意成功 GET 不足以证明逐项事实；集合任务还要证明分页/筛选覆盖。
3. `judgment_sealed`：真实 recipient ID、交付哈希、写前 `accept/repair/reject/unknown`、计划使用/修改/舍弃的行、判断依据、额外公开查证和预计返工；随后 `consumer_action` 逐项记录尝试与真实世界变化，`actual_use_sealed` 记录实际采用/修改/舍弃、返工、额外复核、完成回报及成本。意向与行为不可合并，匹配行为不自动证明由交付造成。
4. `public_outcome` 与 `blind_claim_audit`：前者仅含运行时合法公开反馈，后者对**所有**训练交付盲于策略/终局分数核查内容正确、来源充分、覆盖及生产者/接收者/共同/未知责任。`blind_claim_audit` 是离线分析标签，**不得出现在在线 `role_update` 的可用事件列表**；若要提供在线公开抽审，必须另设预冻结的合法服务与调用成本。若预声明训练期终局二值服务，则所有组同等时间和成本获得，不能用私有 evaluator 断言直接更新生产者。
5. `role_update`：被评 producer、judge、情境、允许使用的事件 ID、更新前后 role 记录/不确定性、judge 可靠度或 abstain 理由；另记 `workflow_update` 的依赖/交接/返工记录与版本。接收者对邻居的局部看法与被评者的可分享 role 证据分字段、按图授权传递。
6. `assignment_sealed`：未来本地 owner、合法候选集合、可见证据 ID、各方法预测/分数、平局和选择概率、选中身份，必须先于未来交付/评分；`offline_evaluation` 仅在两条候选分支都封存后写独立结果文件，含官方 scorer 版本、逐断言结果、任务质量及完整成本。

## 对照、终点、判停

用完全相同的 typed 事件、历史上下文、存储和最大模型/核查预算，预先实现至少一个**强情境信任/上下文 bandit**及[Meta-Team L2 同伴画像适配](../../../references/aamas/metateam_reuse_20260923/README.md)，再与原始 accept 比率、terminal-only、自报/固定角色和打乱 `judge→producer` 关联的机制消融比较。L2 的反思调用计成本；不能把只喂低信息的弱 bandit 称为同信息对照。当前 [APE 压力测试](AAMAS_PEER_JUDGMENT_METHOD_STRESS_TEST_20260923.md)的 Beta 质量+judge 灵敏度更新只是诊断候选：给 bandit 同一历史和同一函数类，它可精确复现该更新与选人；若预测、选择或效用与这些方法不分离，就没有新方法证据。[Meta-Team 原论文](https://arxiv.org/html/2605.29790v1)已包含直接同伴反馈到队友画像和组织改变；[DecisionBench 原论文](https://arxiv.org/html/2605.19099v1)已包含旧轨迹能力卡到后来委派，不能把宽泛“先画像再分工”当新颖。

开发闭环的报告单位是每个 native ID 和情境家族：①未来盲审交付质量的预测误差（如 Brier/逐例概率与标签）；②预先封存的未来局部选择是否与强对照不同，以及该选择在同检查点候选分支中的官方成功、生产者+接收者+审阅/更新/选择总 API 调用、tokens、工具调用和耗时。**任何单一 `success−λ·cost` 主指标中的 λ、费用口径和缺失用量处理，都须在下一次实验前另行冻结；本草案不事后指定赢家。** 短程两次未来选择只可作机制反例或可行性判断，不能给稳定性能或显著性主张。

建议开发判停：若仪器尚不能在预选新 ID 上封存一条完整合法链，停在观察器修复；若 8 条训练链未完整取得（包括 provider UNKNOWN），不把缺失补成负标签或事后换题；若两位候选的盲审质量与角色记录没有可辨识差异，或所有未来预选机会的选择与同信息强对照完全相同，停止昂贵的候选分支实跑并报告“该开发样本没有可辨识职责效果”。若完整、分歧且预定未来 ID 上有积极质量—成本信号，只说明值得设计**独立长期 full-policy streams**，其各组从共同初态开始、可自行形成不同 agent/workflow 历史，不能把候选组的真实记忆复制进基线。

若沿用已用过的 A0 v4 阶段上限 `producer 12 + review 5 + action 7`，8 条训练和 4 条未来执行最多 **12×24=288 次任务 LLM 尝试**；另计选择器、L2 反思、健康调用、公开工具/评分时间及任何超时的未知 tokens/费用。上限是成本预约，不保证 12 条链能完成；真实调用前必须冻结具体 ID、顺序、模型、prompt、来源界限、预留、停机规则、强基线与汇总脚本。所有失败逐尝试留原始 JSONL，不把一次成本高昂的单例探索写成方法成功。
