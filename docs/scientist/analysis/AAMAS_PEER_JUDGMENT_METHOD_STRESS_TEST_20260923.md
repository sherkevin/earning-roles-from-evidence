# 原问题的方法压力测试：同伴证据怎样才构成新方法

2026-09-23。**研究分析，未与作者锁定算法；本文件没有新增实验结果。** 活跃问题遵循[决议 0005](../../user/decisions/0005-retain-peer-judged-role-learning.md)和[0006](../../user/decisions/0006-study-peer-judged-role-formation.md)：协作中的 agent 通过实际接收者对交付的判断、使用和返工，获得后续职责；agent 与工作流由这些交互共同塑造。把一个独立能力包换进固定 workflow 的资格问题不再是主问题。

## 一个可以运行、却不足以当主创新的候选

可把每次交付分成四个先后封存的事件：生产者的逐项来源和行动建议；接收者行动前的验收；实际使用、修改、舍弃、额外核查及其成本；后来合法获得的质量/终局证据。接收者自己执行或完成回报的错误单独记，不因为团队终局失败就扣给生产者。一个透明实现可以为生产者在情境 `z` 的可审计交付质量保存 Beta 后验，为每个接收者保存对可审计事实的灵敏度/特异度；只有具备足够公开证据的审计事件才直接更新质量，其余同伴评价按估计可靠性软更新。局部任务拥有者再依据这些后验、风险和执行/核查成本选邻居。

这只是 **APE 诊断候选**，不是当前论文方法。若把 `source/use/repair/audit/reviewer_id/cost` 全部给同信息、同计算预算的情境信任或 contextual bandit，它完全可以保存相同后验、做相同更新与选择。因此，仅赢过“原始 accept 平均值”或“终局均摊”并不能证明新学习算子。Meta-Team 已有下游同伴反馈、队友画像与组织更新；CADMAS-CTX 已有局部情境信任；Sero 已有信用驱动角色演化；C3 已指出正确上游被错误下游终局连坐的问题，并用固定历史干预估计贡献。[一手来源与边界](AAMAS_PEER_JUDGMENT_NOVELTY_BOUNDARY_20260923.md)、[Meta-Team 代码复用审计](../../../references/aamas/metateam_reuse_20260923/README.md)。

## 先定义可识别的量

1. **信息质量**：交付的每个主张和目标是否由允许的公开来源支持，是否覆盖“全部/最近”等集合条件；来源不足与内容错误分开。接收者 `accept` 和匹配行动不是独立真值。
2. **实际贡献**：在相同任务状态、同一接收者与同等行动预算下，看到生产者交付相对于看不到交付，是否改变核查/返工成本、动作正确率或终局质量。接收者可能自己重查资料；单条匹配动作不能识别这个差值。若要估计，须事先随机化是否展示交付或展示同等成本的替代交付，并按配对世界计入生产、审阅和反事实运行的全部成本。
3. **角色证据价值**：只让后续局部分工策略读取符合权限的同伴事件，相对于获得相同事件的强情境信任/Meta-Team L2 适配策略，是否提高未参与更新的后续任务上的净效用。这个终点需要多个可选 agent、持续身份和真正发生的职责选择；一条交付链或角色分数变化不够。

审计真值若便宜且覆盖全部，直接依赖审计的普通选人器可能更好；若审计太少或只审争议样本，评价者误差不可稳定估计。必须预先规定抽审分布、缺失处理和成本。固定状态重放如果同预算可行，应作为 C3 式责任估计的强对照，不能先验宣称“同伴评价更省”。

## 开发顺序与反证

- A0 只检查通用交付、行动前判断和实际使用/返工能否在四个原生任务家族及预定调用上限内产生；它没有角色更新或无交付物接收者对照。失败只能评价该受限观察协议。
- 若 A0 的观测链能稳定产生，先审全部交付的来源和任务覆盖，再以预冻结预算做“交付可见/不可见”的同接收者配对诊断，估计交付的边际成本/质量效应；把此前已见 train 任务明确标成开发数据。此对照目前**未获预算和配置锁定，不可临时加到 A0**。
- 只有出现有信息量的评价信号、可承受的审计/重放成本及多个候选执行者的可区分证据，才冻结 A1/B 的角色更新与同信息对照，测试后续职责是否改变且改善净效用。即使如此，APE 与同信息 bandit 等价的部分不能写为主创新。
- 若同伴判断不能预测后续可审计质量，接收者总是独立重做，或同信息的普通选人器达到同等结果，记录负结果并收窄论文主张；不靠增加工作流模块或换一个名称补救。

真正检验“从他人判断学角色”的最小开发单元，不能只有一个生产者和一个后续分数。至少让同一情境有两个可选的长期身份，初始模型/工具/提示同质，但各自拥有持续、隔离的合法经历；在配对重置世界中交叉安排生产者和接收者，封存交付、盲审质量与同伴事件。后续任务由局部拥有者依据其获准看到的历史选择执行者；记录是否与同信息 trust/bandit、Meta-Team L2 适配发生分歧，再配对运行有分歧的后续任务。另随机展示/隐藏真实交付，单独估计交付本身对接收者核查成本和质量的边际贡献。短程配对只能做机制诊断，不能代替多个独立长期共演流。现有四家族、每家族三个相关 sibling 且研究侧已接触的任务，最多支持很弱的开发 go/no-go 判断；同一温度 0 模型若没有不同的真实经验，A/B 标签也可能只是同一个策略的重复命名。不能人为灌入预设专长来制造“角色涌现”。

已有 v4+v5 的单一真实案例显示：接收者验收并执行了三笔匹配请求，官方失败来自接收者的 `complete_task` 回报格式；生产者来源引用也不完整。它支持分离证据类型的必要性，**尚不支持**同伴判断的增量预测力、交付因果贡献或角色学习。[原始证据与解释](AAMAS_PEER_JUDGMENT_PILOT_INTERPRETATION_20260923.md)。
