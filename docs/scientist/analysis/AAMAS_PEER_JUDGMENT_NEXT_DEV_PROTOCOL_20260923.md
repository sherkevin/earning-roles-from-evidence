# 原问题下一轮开发实验：从真实同伴验收到后续职责

2026-09-23，**待实现的前瞻性开发协议草案；本文未运行模型、未锁定新方法，也不是确认实验预注册**。研究问题取自[决议 0005](../../user/decisions/0005-retain-peer-judged-role-learning.md)、[0006](../../user/decisions/0006-study-peer-judged-role-formation.md)：执行者交付的工作被实际接收者如何判断、使用和返工，能否形成该执行者在相似后续任务中的角色证据，并改变职责与团队净效用。v4+v5 的[单一案例](AAMAS_PEER_JUDGMENT_PILOT_INTERPRETATION_20260923.md)只证明该观察链在一个任务上可执行；它不进入下面的新样本计数或角色状态。

## 单位、任务和身份

- 一个**原生 AppWorld task ID**是一条独立世界任务；一个 producer→consumer 交付及其后续行动是该任务内的观察单位。家族内三个 sibling 相关，不能当成三个独立家族；不同策略在同一 `_3` task 的重置执行是配对反事实运行，不是新任务。四个家族、共 12 个 train ID 均为已被研究侧接触的**开发材料**，不充当未见确认集。
- 四个身份标签 `A/B/C/D` 从同一 `qwen3.8-max` 路由、系统指令、工具与空初始记忆出发；先前 R0 的 `memory_library`、结果和答案不得进入它们的提示或来源检查。固定候选邻接为稀疏环 `A—B—C—D—A`。**A0 仅做无跨任务角色/技能更新的仪器烟测**，身份标签用于平衡排班和保留各自事件；A1/B 若要引入持续私有经验、角色/工作流记录，必须先另行冻结相同的状态转移与存储上限。任务世界每次按原生 ID 和预定种子重置。身份名与家族、预设专家角色无语义关系。第一轮配对由实验排班表固定以保证暴露覆盖，**不是**论文所提政策的中央选人器。
- 原始 [`idea.md`](../../../idea.md) 的完整愿景还包括无中央调度、局部邻居、递归 `do/outsource/split` 与逐级验收。这里的控制器仅启动世界、强制访问边界、记录和评分；不看私有答案来决定委派。四节点环和单层交付仅检验局部同伴证据的最小环节，不能证明递归组织涌现。上述架构要素是否都是本论文不可让步的硬约束，**待作者澄清**；不能把实验排班误写为最终中心政策。

这四类任务分别需要从公开应用状态识别交易与人、筛选评论/点赞对象、按关系与任务方向筛选待处理请求、识别误收款与退款；都含“先确定目标和参数，再执行写操作”的依赖。`6ea6792_1/_2` 已在 R0 单代理开发中调用过，仍可用作新的同伴交付诊断，但绝非未接触样本；其中 `_1/_3` 要求接受、`_2` 要求拒绝，角色证据必须记录动作方向和关系上下文。它们并非难度等价，分析必须按家族列出而非只汇总。`3c13f5a_3` 已深度续跑，排除在新任务表外；v1 曾超时且声明不重跑的 `22cc237_1` 家族也不进入本轮任务表。

## 一个任务的合法信息流

1. 生产者只读任务说明、公开 API 文档和当前世界的公开 GET；它没有写权限。它交付通用 `candidate_actions[]`：每行动的公开 API 名、目标实体、参数、涉及的事实/计算、逐项**带类型来源** `source_refs`，或带来源的 `no_action`。来源可指不可变的公开任务说明 `task_spec`、确实发生的 `api_observation` 和必要的公开 `api_doc`，须记录字段/值、位置、actor/world/来源哈希；计算值还需列出操作数与变换。在线门只检查公开语法、引用存在及可机械核实的精确字段，不能用研究侧答案替它补足主张。目录列表或任意一个成功 GET 不足以证明逐项主张；含“全部”“最近”等集合条件的任务还需给出公开分页/筛选完成依据，漏项风险单列为未知。收款请求、点赞、评论和退款不能硬编码成同一专用 schema。验证失败只给不含答案的格式/来源反馈，计入同一预算，原答及错误保留。
2. 接收者是**另一个模型调用历史与私有 REPL**，只经封存交付物获得生产者信息；其世界在任何写入前与生产者读取时同源同种子，并以初始公开任务状态指纹核对相等，审计生产者只读阶段没有改变任务状态。接收者可自行公开查证，先封存 `accept / repair / reject / unknown`、拟使用的行动行、具体理由、预计返工及引用。再开启写权限，分别记录行动调用**尝试**、可验证的成功状态变化、逐项使用/修改/舍弃、额外公开读取、返工调用和 `complete_task`。行动前判断与实际行为是两个字段，不能以意向代替使用；内容匹配或成功的请求包装也不能单独证明生产者造成了行动。
3. 记录的角色证据同时指向 `producer_id, consumer_id, family/context, deliverable_hash, public_source_ids, pre_action_judgment, actual_use, repair_cost, public_runtime_outcome, uncertainty`。生产者的角色档案与某一个接收者对它的私下看法分开；可见的带签名验收摘要只沿邻居共享，原始私有记忆不交换。工作流记录保留该次依赖、交付和返工，并允许按所有组共用的版本规则演化；不能把固定工作流包更换当成本研究对象。
4. 官方 evaluator 只在判断、行动和模型可见状态均封存后离线运行。私有代码、答案、断言细节及研究侧人工审核不得进入模型、在线角色更新或重试规则。若另行允许训练期二值终局反馈，须在机器配置中提前声明且所有比较组同时可用；二值终局失败**不得自动扣给生产者**。先按公开轨迹把错误标为生产者内容/来源、接收者审阅/执行/完成回报、共同或未知，再看离线总分；不可由总分倒推责任。v5 的三笔请求正确、`complete_task` 答案字段错误，是必须通过的归因回归样例。B 的两个配对臂都封存后才能揭示任一臂评分，不许按先看到的私有断言改另一臂。

## 两道判停门与对照

- **A0 可先单独冻结并执行仪器诊断**：四个 ID、上述顺序与配对必须在下一次模型调用前进入不可变配置。每例最多 20 次真实 LLM 尝试（生产者 8、审阅 5、行动 7，跨阶段不得借用）；A0 最多 80 次。错误、超时、额外推理 token、未知用量、世界调用、日志写入均计费并留痕。沿用已验证的原生 SafetyGuard/延迟审计方案，先做一次真实 provider 健康调用及零 LLM 原生读写权限 fixture，两者与任务尝试分列。任意 provider 超时仅在世界无动作时允许一次原任务重试，计入本阶段上限；传输状态不明、阶段额度用尽各标明 `UNKNOWN` 原因，不当成语义拒绝或零成本。连续两例同一基础设施错误时停止并保留尚未开始的 ID；停机后未启动的题不进观察率分母，另列删失。若完整运行的 A0 少于 3/4 例封存有效交付、行动前判断和实际使用/返工记录，停止**此有上限的异质任务控制器**，不能推广为原研究问题不可行，也不能挑成功案例替换。
- **A1 和 B 尚不能直接运行**：先把通用 schema、逐项来源核查、角色更新、局部选择器、工作流共同更新规则，以及 raw acceptance 和同信息情境 trust/bandit 的**实际公式/提示/平局规则**另存为冻结配置。若 B 的任务拥有者未亲自评判某个候选，须事先规定邻居之间带来源摘要的转发路径、必达性、相同信息权限与存储成本；不能临场挑选有利评价。A1 固定四例，上限另 80 尝试。只有八例累计至少 6 条完整事件、四家族各至少一条、四个生产者各至少一条，才计算 B 的预行动角色选择。缺失/未定证据必须在规则中规定为 abstain/回退，不能当负例或零成本。若所有 `_3` 的候选与强同信息基线选择完全一致，记录“此开发样本没有可观测分配分歧”，停止 B 的昂贵实跑，不能宣称效果相同。
- 若通过第二门，对**全部四个** `_3` 任务分别从 A1 后同一存档状态新建匹配世界，运行候选局部选择器与至少一个同信息情境 trust/bandit 选择器；raw acceptance、terminal-only 与固定/自报规则可先做无额外模型调用的影子选择，但最终论文的强比较必须实跑。候选与对照都获得相同合法事件、模型/工具/存储限额和初始快照，连评判、额外核查、选择与工作流维护成本都计入。克隆快照 B **仅隔离后续分配箭头**；它不等于各策略各自在线发展出来的完整共演对照，不能替代未来独立长流实验。B 最多 `4×2×20=160` 尝试；全协议最多 **320** 次任务 LLM 尝试（A0 80 + A1 80 + B 160），另记健康调用；达到上限原地停止，保留未完成及未知结果。任何新增无交付物接收者对照必须先修订预算和协议，不能临时添跑。

## 指标与可否继续

首要读数是完整交付/行动前判断/实际使用率、逐项来源支持率、接收者公开复核与返工成本、`judgment ≠ actual_use` 的不一致、生产者与接收者各自可归因错误、四个后续机会中的选择分歧及配对官方任务结果/总成本。研究侧按预定 rubric 对**全部**交付逐项审公共来源与行动轨迹，标记 `supported / unsupported / indeterminate`、错误责任 `producer / consumer / shared / unknown`；盲于策略和官方总分后再揭示，分歧保留。报告每任务原始值、按家族汇总和小样本不确定区间；四家族不能支撑稳定的评判者校准、优势显著性或“涌现组织”结论。

若接收者独立重做所有识别、没有省下成本，或情境 trust 使用同一证据得到相同/更好选择，就把它记录为对论文主张的反证或收窄依据。A0 没有无交付物接收者对照，故其中观察到的匹配行动不能估计交付的边际质量或时间收益；这类对照若要加入，必须先修改并冻结预算。只有观察质量、角色记录、后续职责、净效用与近邻基线都显出值得扩展的迹象，才另行设计独立确认集和完整在线共演策略流；不从这批已知 train 任务推断中稿率或确认方法有效。

每次运行前存配置、源码/依赖 SHA、AppWorld commit/data version、任务/种子/模型路由、工具权限和预约预算；运行中逐尝试写 JSONL（提示哈希、响应、用量、错误、耗时、公开 API 调用、交付/验收/使用/更新/选择），之后另存逐例原始结果、官方离线评分、按家族处理表与人可读报告。任何 API key 均删去；缺失输出保留为缺失。未来确认任务须在本地标签已可见的条件下建立独立进程/权限隔离，并在读任何确认结果前冻结完整协议。
