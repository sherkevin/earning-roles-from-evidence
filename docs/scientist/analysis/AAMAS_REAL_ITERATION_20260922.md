## 先验证故事线的第一环

原问题可以收紧为：**新经验改变了执行能力以后，如何用可复用的协作要求，
以较低测试成本决定在哪里采用这个更新？** 私有经验、角色和工作流分别承担
产生候选能力、按证据授权、保存协作要求的作用，不能直接当作三个创新点。

这条链需要检验经验是否产生了与研究目标有关的变化。记录了多少经验、出现
多少角色，或者程序读起来更规范，都不能代替这个证据。第一轮仅以完整任务
成功提升作为一个候选包的晋级条件；它没有直接检验协作机制。Q1 允许局部
质量持平，有用变化也可能表现为同质量下的资源节约或下游贡献，不能把本轮
成功提升门槛扩大为整个方向的逻辑前提。检验其他目标需要另行预先规定，
不能据此事后改判本包通过。

## 第一轮：完成真实调用，未通过原定晋级规则

使用 cc-switch 的“内部”配置、idealab 实际接口和返回名为 qwen3.8-max
的模型。AppWorld 使用固定源码与数据、原生提示、独立初始世界和官方评分。
模型解题时不读标准答案；经验归纳只收到公开执行轨迹和训练任务的最终成功
布尔值。完整请求、响应、报错、原始状态与哈希均留在本地。

按事先固定的哈希顺序选六个训练家族，用各自第一个实例获取经验，再用第二个
实例比较相同模型的无经验与带经验版本；另重复两个预定无经验任务。

| 指标 | 无经验 | 带经验 |
|---|---:|---:|
| 六个配对任务的最终官方成功数 | 6/6 | 6/6 |
| 配对阶段实际请求次数，含错误 | 96 | 99 |
| 已知上下文 tokens，含缓存读取 | 739,410 | 886,460 |
| 报告的输出 tokens，含推理 | 14,968 | 13,430 |

获取经验、原始中断及其预先声明的修复、六次归纳合计 **102 次请求**；
配对验证 195 次，重复对照 32 次，合计 **329 次真实实验请求**。
另有两次接口健康检查，单独记录。原报告的获取小计 86 漏分了 16 次修复；
总数始终正确，旧报告、修正原因与独立复核回执均已保留。
未知用量的失败请求没有被记为零成本；没有价格信息，不能给出准确金额。

原门槛要求至少两次配对成功提升，实际为零。另有一个最终成功的样本出现过
未被协议豁免的 HTTP200 空文本响应，因此仍不是干净的基础设施样本。
两份最初因存储路径包含 `memory` 而无法评分的结果，只复制原有状态重新评分，
没有让模型重做任务。上述处理都不改变原门槛。

结论是**不晋级这个经验包，不运行其条件式 dev 对照**。六个样本不能证明所有
经验学习都无效；输出 tokens 的下降也不能在其他资源增加时被概括为整体省钱。
详细结果见 [实验报告](../../../artifacts/experiments/aamas2027/dev_20260922/report.md)。

## 轨迹解释了什么

独立审查覆盖全部六对轨迹，先遮蔽实验组标签，再揭盲核对。审查者已经知道
聚合结果，所以这是标签遮蔽分析，不是完全盲审，也不是预先声明的新终点。

分页、ID 去重、跨服务连接和先收集后修改等程序，大多在两侧都已出现。
两侧部分执行轨迹不同，但尚未区分经验影响与运行波动，也没有测出有用的
新能力。同一无经验任务的重复执行也出现过请求数从 20 次变为 18 次。
请求增加最明显的一例是文件压缩：
带经验版本逐项压缩、检查文件存在、手动删除，使用 26 次请求；无经验版本使用
原生压缩并删除选项等操作，使用 15 次。这一例没有体现额外检查的收益，
也不能据此证明归档内容完整或原生 API 具有原子性。

六对中四对的带经验执行请求更少、两对更多；其中一对较少请求的运行存在
上述未豁免响应错误，五对合规比较中为三对更少、两对更多。压缩一例增加
11 次，而六对合计增加 3 次，不能由这一例推断任务普遍变慢。单次配对及
缺少通用建议／长度匹配对照，也不足以把较少请求归为稳定的经验内容收益。

完整 dev 普查期间，已出现两个同家族失败：模型把“喜欢”条件作用于歌单或
专辑，再下载其中的歌曲；最终检查的是自己所选集合是否处理完。官方评分
拒绝最终状态，而相应歌曲库变体成功。这个差异提示了谓词作用对象问题，
但任务措辞的歧义与反事实修复效果仍须区分，不能把解释直接当因果结论。

这给方法设计一个具体约束：交接只带“合法歌曲 ID”不够；共同语义接口还应
暴露动作对象、筛选条件作用对象、来源范围及公开执行证据。这首先是所有
强对照都应具备的能力，不能只给本方法后再宣称协作优势。

还有一个可复用的训练线索：`692c77d_1` 的真实代码已经正确计算“歌单中歌曲
ID 集合 ∩ 喜欢的歌曲 ID 集合”，随后执行评分操作。但归纳候选写成了
“playlist IDs”，对象表述有歧义。它与 dev 下载任务形成跨动作的可能迁移，
尚未接受干预检验；不能直接称为已获得的新能力。原经验没有被事后修改，
[对照记录](../../../artifacts/experiments/aamas2027/dev_20260922/cross_action_scope_audit.json)
区分原始观察、归纳表述和未经验证的解释。

## 第二轮：完整开发集环境诊断

独立的 [57 项普查协议](../../../configs/aamas2027/headroom_census_v1.json)
在调用前已冻结，落实项目既有 B5.2。全部原生 dev 实例各跑一次无经验版本，
不筛难题，不换模型，不缩短提示或预算，不添加经验或归纳调用。
每项最多 30 次请求，最多 1,710 次；实际额外推理用量按服务返回值计。

原控制器在第 27 项后按规则停止：23 个有效成功、2 个有效失败、2 个网络
中断未知，共 433 次请求。连接恢复且一次独立真实健康请求成功后，
[基础设施修订](../../user/decisions/0004-continue-unstarted-census-after-outage.md)
仅续跑原顺序未开始的 30 项；两个中断不重跑、不改成模型失败。修订发生在
看到部分结果之后，已明确披露。恢复再次遇到运输或进程失败就永久停止。

恢复完成原顺序的 10 个有效成功后，第 11 项出现两次 TLS EOF 错误，控制器
按规则永久停止。最终 **38 项已尝试：33 个有效成功、2 个有效失败、3 个基础设施
未知；19 项未开始**。完整分母下成功数仍可能为 33–55/57，不能用干净子集的
33/35 冒充全 dev 成功率，也不能宣布饱和或已有足够提升空间。
[停机报告](../../../artifacts/experiments/aamas2027/headroom_20260922/report.md)
与 [冻结结果](../../../artifacts/experiments/aamas2027/headroom_20260922/stopped_summary.json)
保留原始停机及事后基础设施修订的全过程。

“有效”指符合原协议；其中一个失败有一次已允许恢复的 429，并非所有请求
都无错误。两项有效失败已全部标注，三个网络中断独立列为 UNKNOWN，没有把评分器对
未完成状态的拒绝算成能力失败。普查实际用了 **592 次请求**，其中恢复为
159 次；共有 9 次错误请求用量未知。没有启动第二次恢复或补跑失败任务。

原规则是成功数不超过 5 或达到 52 时停止这个成功率提升研究配置；至少六个
有效成功和六个有效失败，只说明存在提升空间。基础设施问题保留为未知并
传播到成功数上下界，不能冒充模型失败。这个未完成普查不触发新干预组。

跨两轮和健康请求的 [总账](../../../artifacts/experiments/aamas2027/iteration_20260922/accounting.json)
直接核对原始 request 事件：924 次请求，已知上下文 7,630,857 tokens，
输出含推理 180,578 tokens，16 次请求用量未知；金额无法从现有价格信息确定。

## 创新边界与接下来必须解决的实质问题

本轮重新检查了 SkillMAS v2、Meta-Team v1 及 Meta-Team 的后续固定代码提交。
它们已覆盖程序归纳、有限修复、技能修订与删除、按需消费经验，以及持久化
下游协作反馈。代码中的内容或格式检查不能被自动当作独立能力验证。
两篇正文及关键实现已 [下载并标注来源](../../../references/aamas/acquisition_followup_20260922/README.md)。

因此，下一学习器至少要与“同信息、可修订、按需使用、允许不更新的程序库”
比较；第一轮全量拼接六份摘要只是前提探测，不能作为唯一强基线。
超出共同 API 文档的可学信息，应是某种条件下实际发生的错误、下游怎样使用
输出，以及修改以后观察到什么变化。泛泛分页建议不能承担整篇论文的创新。

仍可研究的区别是：在没有精确模型或免费验证 oracle 的条件下，从有限反馈中
得到协作要求，复用到未见过的组合，并以较低资格测试成本保持任务质量。
这目前是问题，不是已经实现或已经证明新颖的方法。对当前有限条件机制，须给出表示语言、
学习与测试选择规则、未知情况的处理，以及一个单独明确的迁移范围。
若每个新组合仍需要完整重跑，或者共同接口与普通回归测试已经解释全部收益，
就没有证明这个区别。

为验证后续所需的重放条件，另做了一个零 LLM 调用的
[原生环境试验](../../../artifacts/experiments/aamas2027/replay_fixture_20260922/report.md)：
同一训练代码在两个新世界中的逐步观察和数据库状态一致，各使用 45 次本地
环境 API；仅复制数据库到第三个世界后，续执行缺少先前变量，并在退出时
触发原生时间控制异常。它是保留失败的部分验证，不能被称为完整重放通过。
后续需重建变量与消息历史，并计算前缀重放成本；当前没有免费反事实 oracle。

当前没有依据锁定投稿方法或预测中稿率。本轮已分析全部观察到的有效失败，
仍未建立有用更新与消费者的真实交互。第一轮经验包停止晋级，第二轮保持
基础设施导致的不确定结论；不把失败样本改成有利的评测子集，也不通过添加
模块绕过原来的失败结果。

[独立方法取舍](AAMAS_Q1_FEASIBILITY_REVIEW_20260922.md) 已具体列出表示、
提案、测试选择、UNKNOWN 与唯一迁移单位的边界。现有信息能实现完整任务
回归筛选；尚不能把它改称为更便宜的协作资格机制。

此前提出允许删减私有经验、贡献证据、可复用工作流，是降低复杂度的研究
管理建议，并不是本轮实验推导出的结论。再次复核后，当前证据不足以识别
哪项设定应该删除；项目继续保留三项。下一步讨论应先明确它们共同解决的
一个决策问题及相应检验，再依据组件对照决定哪些能承担论文主张。此建议
仍待讨论，不构成新的方法共识或实验协议。
网络中断也尚未被根治。若后续继续这项普查，必须明确记录新的基础设施处理
和协议决定，保留原中断、未完成状态和全部成本，不能静默绕过已触发的停止。

已可复用的实际成果包括真实 provider 适配器、原生环境与评分调用、冻结清单、
六份来源明确的经验候选、所有训练/验证轨迹、逐请求成本账本、无新增实验
API 调用的失败分类工具，以及上述近邻方法代码资料。它们已保存为本地文件。

## 2026-09-23：远端后续进展，不回写上面的旧实验结论

已获取远端 `iteration/r3-program-control-20260923`，最新提交为 `e873d70`。
这条分支在原两项有效失败及一个同家族成功任务上追加了 R1、R2、R3 原生
环境重放。它们使用保存的公开轨迹，研究者指定交接边界和后续代码，不能
视为在线自主学习的任务成功率实验。当前工作分支尚未合并远端提交；下列
本地结果文件已与对应远端 Git blob 逐一核对相同。

- [R1 三臂结果](../../../artifacts/experiments/aamas2027/role_contract_20260922/native_summary.json)：原执行、有限交接、单一程序对照在三个实例上的官方成功分别为 1/3、1/3、1/3；单一程序逐项解释有限交接结果，未见新增机制收益。零次新任务策略 LLM 调用。
- [R2 因子重放](../../../artifacts/experiments/aamas2027/handoff_effect_20260922/native_summary.json)：加入一个消费者端 `exclude_already_done` 检查后，原选择为 1/3 成功，同检查下语义选择为 3/3；两个旧失败在语义选择加检查组合中转成功。另有一次真实 LLM 调用归纳共同检查，六个新原生世界、196 次环境 API。它是事后、同家族、固定轨迹的诊断，不是独立验证集效果。
- [R3 同来源程序对照](../../../artifacts/experiments/aamas2027/program_control_20260923/summary.json)：三次新原生执行全部成功，并在选中集合、官方评分、12 个数据库文件字节及环境 API 次数上逐项复现 R2 语义选择加检查臂。新增零次任务策略 LLM 调用；原报告据此标记 `PROGRAM_EXPLAINS_R2`，而不是本方法的独特机制成立。

这些重放在原生环境中实际改变了执行代码的数据交接，且揭示了语义选择与
消费者检查的局部交互；它们尚未构成独立自主 agent 的协作证据。R3 加强了
“同来源普通程序足以解释结果”的替代解释。它不撤销原六份经验包未晋级和
完整 dev 普查不完整的结论，也没有形成 Q1 的可迁移资格学习器。若后续
主张独特协作学习收益，需要脱离这三例的事后边界选择，在独立任务和真实
在线策略调用中与同信息普通程序、可修订经验库比较，并计入获取与测试成本。
