# A0 v4：同伴交付观察链的四题开发诊断协议

2026-09-23，**前瞻性冻结于 v4 的任何模型调用之前**。09:24 UTC 的执行前修订明确加入探索输出可见性和及时封存规则；此前草案未触发 v4 provider/任务调用。这仍是已知 AppWorld train 任务的开发诊断，既不是未见确认，也不是角色学习效果实验。本文独立于 [A0 v3 所引用的原协议](AAMAS_PEER_JUDGMENT_NEXT_DEV_PROTOCOL_20260923.md)；v3 的协议、配置、runner、原始数据和结果均不改写。

## 为什么进行 v4，以及不能怎样解释

v3 按预先规定的四题顺序全数尝试，共 32 次任务 LLM 调用，四题均在生产者阶段成为 `UNKNOWN`：三题达到 8 次生产者调用上限，一题发生超时；没有一条完整的交付→事前判断→实际使用观察链。v4 是**看过 v3 结果之后**修正仪器的开发重跑，不能把同四题算作新样本，也不能把 v4 相对 v3 的改善当作方法效应。必须保留全部四题，包括 v3 最费时和超时的一题，不能按结果换题、换顺序或挑成功题汇报。

v4 针对在公开轨迹中暴露的执行障碍：原生产者预算经常花在发现登录入口、查询账户名及凭据上；第四题曾调用文档 API 却没有 `print` 返回值，导致探索结果对下一轮不可见；原超时重试规则只允许世界从未执行代码，即使当前请求本身没有返回任何内容也会被禁止重试。因此统一给予两个 actor 相同的**公开登录与探索输出提示**，将生产者上限从 8 提至 12，并允许一次条件严格的同请求超时重试。除此之外，沿用 v3 的 task ID、配对、世界种子、模型、输出上限、来源验证、状态/评分隔离与终止解释。更长预算是成本增加，不作为算法贡献。

| 2 | `afc0fce_1` | `B→C` |
| 3 | `6ea6792_1` | `A→D` |
| 4 | `60d0b5b_1` | `D→C` |

四题均用 AppWorld `0.2.0`、源提交 `42b5bcf3cd334fee33f0c37c02070a9f5807add5`、种子 `100`；`内部` 路由的 `qwen3.8-max`，温度 `0`，每次输出上限 `8192`。每题尝试上限分别为生产者 `12`、接收者审阅 `5`、接收者行动 `7`，共 `24`；四题总任务调用最多 `96`，健康检查另计。所有调用尝试（含超时、服务错误和格式拒绝）均按所属阶段计费；阶段额度不得互借。四个身份仍为空初始私有记忆且不跨题更新角色，第一轮配对仍只是仪器排班。

在两位 actor 的初始提示中加入相同的、与题目答案无关的登录指导：需要登录时，先查询目标 app 的公开 `api_docs` 中 `login` 签名，依据 actor 可调用的 `supervisor` 账户资料与账户密码 API 查找对应 app 的账户名和凭据；不同 app 的用户名格式可能不同，按文档参数调用 `/auth/token`。只允许原生公开 API 查询和认证，禁止猜测或硬编码凭据；不把任何凭据、token 或密码回显到交付物、人工报告或可见角色事件。该指导不提供具体账号、目标实体、动作或答案。生产者只读，认证用的 `POST /auth/token` 是唯一例外。

同一通用初始提示还明确：探索性 API 调用须在原生 REPL 中 `print` 返回值或所需非敏感字段，才能供下一轮使用；密码和 token 只保留在 REPL 私有变量，不输出。生产者在公开证据足以支持提案且仍有额度时，应及时封存 `<proposal>`，包括覆盖范围和不确定性；不得为了耗尽预算而继续无关探索。若未取得支撑任何候选或 `no_action` 的证据，额度耗尽即记 `UNKNOWN`，不能编造空行动或强行断言无行动。

## 单题执行及审计边界

生产者在只读世界中由公开任务说明、API 文档和公开 GET 建立通用 `candidate_actions` 或带证据的 `no_action`。每个候选的选择、目标与所有非秘密参数须有逐项带类型 `source_refs`，派生值列出操作数与变换；集合范围、分页与停止依据单列。在线验证仅核对可机械验证的公开来源，不代替语义审核。格式/来源拒绝反馈不含隐藏答案，计入同一生产者阶段。

接收者只获得封存交付物，拥有独立模型调用历史和重置的相同初态世界。其公开查证后先封存 `accept / repair / reject / unknown`、拟采用的行和理由，然后才能写入；审计实际 API 尝试、可观察状态变化、逐行使用/修改/舍弃、返工及任务完成。判断意向与实际使用分开，匹配行动不能单独证明因果依赖。生产者和接收者初始化及生产者读阶段的原生状态哈希需一致；密码及 evaluator 只留在受控位置。

官方 evaluator 只在交付、判断、行动、使用与角色事件均封存后离线调用，其答案/断言不进入 actor 提示、重试或在线角色状态。最终失败按公开轨迹分离生产者内容/来源、接收者审阅/行动/完成回报、共同与未知责任。特别保留“行动正确但 `complete_task` 最终答案错误”的独立错误类，绝不由零分直接扣给生产者。A0 不启用角色更新，也不检验后续任务分配或方法收益。

## 传输、停机和可报告结果

- 对一次 `TimeoutError`，只在该请求**没有返回任何模型响应、没有解析/执行其新代码、消息列表和参数保持字节级相同**，且本阶段仍有余额时，最多作一次完全同请求重试；此前完成的世界步骤不构成禁止条件。整个单题最多用一次这种超时重试。重试仍占所属阶段尝试额度，原错误和未知 token 用量留在 JSONL；若再次超时或余额不足，标记 `UNKNOWN/transport`，不能假装失败或重造上下文。
- 对 `429/503`，至多两次完全同请求重试，1、2 秒退避，均计费；其他传输错误不重试。若错误请求有不确定的响应或执行状态，禁止重试并标记 `UNKNOWN`。不能将服务故障伪装为语义拒绝。
- 生产者越权写、初态不一致或审阅读阶段改变原生状态时全局停止并保留未启动题；连续两题同一基础设施故障亦停止。调用上限导致的缺失标记 `UNKNOWN/cap`，保留逐步原始记录，不换题。
- 每题必须落盘冻结配置/runner 哈希、时间、环境、原生任务 ID/种子、每次真实模型尝试与 token/错误、原生 API 审计、来源、提案、事前判断、实际使用、角色事件、独立 evaluator 结果以及失败栈。最少 3/4 题形成有效且已完成行动阶段的完整观察链才考虑 A1；否则仅停止这一有限预算仪器，不推出原研究问题无效。所有四题和删失分母都报告。

与 v3 相同，`6ea6792_1` 另有 R0 单代理开发暴露；这四题都不称为未见确认。A1/B 的角色更新、局部选择及同信息对照须另行冻结；v4 不替它们预选参数或根据评分调整研究问题。
