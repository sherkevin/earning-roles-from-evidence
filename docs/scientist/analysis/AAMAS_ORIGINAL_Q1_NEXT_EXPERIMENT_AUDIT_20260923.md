# 原 Q1 最小后续实验：独立方法审查

2026-09-23。仅审查[原问题最小闭环](AAMAS_ORIGINAL_Q1_MINIMAL_LOOP_20260923.md)、[交付可见性配对开发协议](AAMAS_DELIVERY_VISIBILITY_PAIRED_DEV_PROTOCOL_20260923.md)、[机器配置](../../../configs/aamas2027/peer_delivery_visibility_dev_v1.json)及已有记录；本审查未修改 runner/config，未调用 LLM API，未验证任何新方法效果。[决议 0006](../../user/decisions/0006-study-peer-judged-role-formation.md)确立的对象是 **agent 与 workflow 在协作中共同变化**，不能把固定流程中的人员替换重新当成主问题。

## 结论：保留诊断，但不要把诊断当成闭环

当前配对协议的唯一干预是让全新接收者看见或看不见一份事后选中的旧交付；它能诊断这份交付在一个 AppWorld 开发任务上的边际质量和成本。两个新世界相互匹配，却缺少与**产生旧交付的历史世界**逐表相等的初态指纹；visible 还要计入历史生产者的 7 次调用，因此这不是等总预算的实时协作比较。它**不能**检验同伴判断能否学出被评价者的角色、这些角色是否改变未见任务的职责，也不能检验 workflow–agent 共演。协议已如实标注这些边界；[无 LLM 原生 fixture](../../../artifacts/aamas2027/runtime_checks/peer_delivery_visibility_native_v1_20260923/result.json)通过只证明隔离/门禁的部分前提，不是模型实验。配置在本审查读取时仍为 `DRAFT_FOR_INDEPENDENT_REVIEW_NO_MODEL_CALLS`。

需分开识别三件事：`D`＝展示交付对**同一接收者**行动与完整系统成本的影响；`P`＝某位真实接收者的判断/使用/返工对生产者**后来独立交付质量**的预测力；`R`＝依据这些事件形成的角色证据，是否改变未来职责并改善完整策略流的官方任务质量—总成本。即使 `D` 显示有利效果，也不推出 `P` 有预测力，更不推出 `R` 能改善后续分工。共演的完整效用只能比较从相同初态出发、但允许各方法自己产生不同记忆和 workflow 历史的长期流；短程克隆只能解释局部机制。

## 六个必须关闭的识别缺口

1. **学习者的信息集。** 在线角色更新只能读运行时合法可见的交付、接收者行动前判断、实际使用/返工、公开后果及先前获准传播的事件；`accept` 或实际使用不等于交付正确。离线盲审和私有 scorer 只能用于分析，不能回灌。若要用训练期终局二值或公开抽审来校准评判者，先说明何时、向谁、以何种费用提供；只有选择性审计时还须处理缺失偏差。对照应有相同原始 typed 事件、信息到达时间、通信权限、存储与总预算；长期流中允许各方法因不同决定形成不同历史，不能把候选方法的实现后记忆复制给基线。[最小闭环的事件表](AAMAS_ORIGINAL_Q1_MINIMAL_LOOP_20260923.md#必需事件和信息边界)已列字段，但还没有指定从合法事件到行动的可复现更新函数。
2. **被评者的角色与委派者的信念不是一个变量。** 应分别定义 `P_v`：关于被评 agent `v`、带评判者/情境/来源/不确定性的可传播职责证据；`B_u(v)`：委派者 `u` 对 `v` 的私有、情境化判断。谁写 `P_v`、谁有权核验/转发、`v` 能否改写以及接收者看见什么都须冻结。现有 `A/C` 为交付者、`B/D` 为接收者且未来由 `B/D` 选人：选人者都曾直接判断候选者，因此即使后续决策变好，也可能只是 `B_u(v)` 的局部信任学习，无法识别 `P_v` 的独立作用。若主张角色证据能跨同伴传播，至少有一次 **未直接评价候选者的第三方 owner** 在固定通信预算内据获准记录作未来选择，并与能读相同记录的情境信任对照比较；否则收窄为“局部选人”，不要称可传播角色形成。
3. **预置席位掩盖角色形成。** 四环安排中 `A/C` 始终生产、`B/D` 始终审阅/行动，且 AppWorld 的只读/写权限人为划分；这最多检验谁挣得某种**既定上游交付职责**，不是自由形成多种角色。最小开发试验可诚实限定这一种职责；若论文要声称更广义的涌现分工，后续必须让同一身份在可比权限下有机会承担不同职责，并预先定义角色变化的可观测量。
4. **角色必须在后续未见任务被真正使用。** `x3/y3` 是同两个家族的相关 sibling，且研究侧已接触训练来源/部分 scorer；它们只能做开发反例，不能当未见确认。未来 owner 的选择必须在任何候选交付/评分前封存，选中的 agent 要在 live 流中实际执行，并让由此形成的私有记忆与 workflow 状态进入下一任务。未选候选的隔离克隆仅供离线估计选择后果，不得写回 live 学习者。需要独立来源任务/家族的长期确认流；报告单位是任务流/家族，而非 12 次执行或 API 调用数。
5. **workflow 不可冻成被动模板。** 实验组只能共用初始流程、允许的动作/更新语法、任务机会与预算。运行中记录 `W_t→W_{t+1}` 的实际依赖、交接、复核/返工和复用决策，并显示这些变化如何与 agent 的私有经历、`P_v` 和后续职责相互影响。所有组用同一非目标 workflow/skill 更新规则，但可因不同选择形成不同状态。若完整实验始终是固定的“只读生产者→写入接收者”链，`workflow_update` 只是日志字段，结论必须缩成固定流程中的交付者选择。要单独宣称“共演机制优于不共演”，还需预先设计冻结 workflow 更新的消融；目前不能由一条配对试验推出。
6. **AppWorld 只适合作开发筛查。** [原生协作基准审查](../../../references/aamas/native_collab_benchmark_20260923/README.md)指出 AppWorld 本是单 agent API 任务；拥有相同读权限的接收者可以重做生产者调查。[已完成的 v4→v5 案例](../../../artifacts/experiments/aamas2027/peer_judgment_resume_v5_20260923/report.md)仅观察到验收和匹配动作，终局还受接收者回报字段影响。因此应先用已封存单例和**预选、不同家族的新开发任务**做交付可见/隐藏配对，计入生产者成本，保留所有删失；按[原闭环草案的门 0](AAMAS_ORIGINAL_Q1_MINIMAL_LOOP_20260923.md#门-0先看交付是否真的帮到接收者)，若三个预选家族中接收者独自完成的官方质量均不差、完整成本均不高，且重做了关键公开查证，停止把该人工拆分作为主 Q1 基底，转向有真实协作依赖的适配环境。不能靠削弱接收者、泄露答案或事后挑题制造交付价值。

## 建议的最小后续实验与严格停机

先完成当前 paired-dev 的冻结、真实 provider 健康回执与隔离检查，再做**交付是否有边际价值**的有界开发门；单例正负均不能升级为角色结论。下一门才冻结一条完整算法：合法事件 `e_t` 如何更新 `P_v`，owner 如何从获准的 `P_v`、`B_u(v)`、自身任务和 `W_t` 决定职责，以及审阅/行动后 agent 私有记忆与 `W_t` 如何依共同规则更新。给出一条手算轨迹、一个 `UNKNOWN`/拒绝更新例和同输入必得同动作的实现检查。只保留**一种角色决策**作为主因果问题；技能生成和 workflow 演化可以是共同环境动态，不能同时包装成三个新增算法。

开发实验至少要有两个持续、可互选的候选身份、真实接收者的多次交叉判断、一次先于评分封存的未来选择，以及一个能区分 `P_v` 与 owner 私有 `B_u(v)` 的第三方选择机会。用同样事件、同样通信和成本实施原始验收率、强情境信任/contextual bandit、Meta-Team L2 式同伴画像及打乱判断来源对照；简单对照若在相同函数类下能精确复现候选更新和选人，就没有独立方法证据。[方法压力测试](AAMAS_PEER_JUDGMENT_METHOD_STRESS_TEST_20260923.md)已指出 Beta/可靠度候选的这一等价风险。完整效用需另在从共同初态启动的独立长期流测量；每组可以形成自己的 agent/workflow 历史，预冻结官方质量、总调用/tokens/工具/耗时和任何质量—成本汇总规则。

**停机规则必须先于目标调用固定：**隔离、真实来源、权限、密钥或评估泄漏失败立即停；传输/额度删失记 `UNKNOWN`，不得补成低质量或按结果替题。若预选开发家族没有可复现且计入生产者后仍有价值的交付，停用 AppWorld 人工两席主环境；若盲审交付质量与同伴判断没有可辨识关系，或持续身份未产生可测差异，停在信号/能力门；若未来职责与同信息强对照始终不分歧，停止昂贵的候选克隆与长期扩展，并如实报告简单方法解释；若只见固定链或只在相关 sibling 上有效，不能声称 workflow 共演或未见任务迁移。任何有利开发结果也只授权另行冻结独立确认协议，不构成已验证或可中稿结论。
