# 原 Q1：接收者证据到产出者职责的最小算子候选

2026-09-23。**待审的可执行研究候选；不是作者确认的方法、预注册、创新结论或实验结果。** 本文没有调用 LLM API，也没有修改现有 paired-dev runner/config。[决议 0006](../../user/decisions/0006-study-peer-judged-role-formation.md)规定研究对象是协作中共同变化的 agent 与 workflow；这里的算子仅定义“某次真实接收者事件如何改变被评产出者以后获得一类职责的证据”，不将固定 workflow 中替换一个执行包重新作为主问题。

唯一值得单独检验的**经验假设**是：在有依赖的工具任务中，真实接收者的行动前判断加上之后的逐项使用/返工，比仅有终局回报或一般声誉，更早、更经济地预测某产出者在相似职责中的**下一次可用交付**，并因此改善之后真正发生的职责选择。下列算子只把该假设变成可复核的程序；它不证明方法区别于同信息 contextual bandit。

## 状态、事件与合法信息

时刻 `t`，agent `v` 的私有技能/记忆为 `M_v,t`，当前协作结构与依赖为 `W_t`。两者按所有比较组共同声明的非目标规则继续更新；不同组可因选择不同而形成不同历史。本文只更新可传播的产出者职责证据 `P_v,c`，其中 `c` 是预先声明的**产出职责情境**（例如“从公开账单提出付款对象和金额”），而不是预先授予 `v` 的角色。任何身份仍可在合法机会中做产出者、接收者或局部 owner。owner `u` 对邻居的私有看法 `B_u(v,c)` 单独保存，不冒充 `P_v,c`。

一条合法事件按时间封存为：`(event_id, task/family, context c, v, recipient j, delivery_hash, per-claim source_refs, judgment_before_action, planned_use, actual_claim_use, producer_attributed_rework, public_feedback, costs, W_version, M_v_version, visibility_scope)`。`source_refs` 必须指向此前合法公开读取的具体事实；目录读取或仅有交付文本不等于事实被证实。`judgment_before_action` 可为 `accept/repair/reject/unknown`；实际采用、修改与返工在行动后另记。生产者不得写自己的评价记录，传播须按图权限并计通信/存储成本。

在线可读：上述已封存且被授权的公开事件、事先冻结的校准参数、训练期**明文声明且向所有方法等价开放并收费**的公开抽审结果。不得读私有 scorer、隐藏标准答案、未来任务评分或研究者离线盲审标签。私有评分与盲审只用于事后检验。若公开抽审服务无法合法提供，不能把研究者的离线标注偷偷用作在线校准。

## 一次更新：观察到的接收者信号不是“贡献真值”

先定义交付级目标 `G_e=1`：逐项内容与来源在职责 `c` 的公开事实审查中有效且覆盖任务条件。它不是终局成功，也不是交付相对于接收者独做的因果增益。审查只在预先抽样的训练交付上、由独立过程用同一公开事实完成，并向所有组提供同等的费用和时间；其余交付的 `G_e` 在线未知。

从真实接收者可观测行为形成 `H_e∈{1,0,⊥}`：

- `1`：行动前 `accept`，后来确实使用至少一条有充分来源的关键主张，且没有来源明确的产出者错误返工；
- `0`：行动前或行动中指出有具体公开事实支持的产出者错误，并拒绝或修复相应主张；
- `⊥`：超时、未交付、来源不全、未实际使用、仅有接收者自己的错误、无法确定返工归属，或 `accept` 与后续行为冲突。

`⊥` 不转成失败或零成本，且不更新职责证据。[现有 v4→v5 单例](../../../artifacts/experiments/aamas2027/peer_judgment_resume_v5_20260923/report.md)虽然出现行动前验收和匹配行动，但生产者逐项引用不足、接收者又独立核查；其终局错误在完成回报格式。按此严格规则，它不能当成已经证实的正贡献。

在独立的、合法公开抽审校准交付上，按 `j,c` 预估两个条件频率：`t_jc=Pr(H=1 | G=1,H≠⊥,j,c)` 和 `f_jc=Pr(H=1 | G=0,H≠⊥,j,c)`。用 Beta(1,1) 平滑频率；须先有该 `j,c` 至少两例 `G=1`、两例 `G=0` 的可判定抽审，且 `t_jc>f_jc`，否则该评价者在此情境不获准产生在线职责更新。校准样本、筛选规则和全部费用预冻结；只审争议样本会有选择偏差，不能照此解释频率。这里的频率仅描述观察信号，不等于评价者对反事实贡献的准确率。

对每个 `v,c` 保持有限网格 `p∈{0.005,0.015,…,0.995}` 上的分布 `P_v,c(p)`，初始均匀。`p` 是当前产出者在此职责中下一份交付通过上述公开内容审查的概率。每个任务开始前，以固定 `δ` 混入均匀先验以允许能力漂移；`δ`、情境标签和网格在试验前冻结。已获准的 `H_e` 到达后执行**一次**更新：

```text
P_minus(p) = (1-δ)·P_old(p) + δ·Uniform(p)
L_e(p) = p·t_jc + (1-p)·f_jc                  if H_e = 1
       = p·(1-t_jc) + (1-p)·(1-f_jc)          if H_e = 0
P_new(p) = P_minus(p)·L_e(p) / Σ_q P_minus(q)·L_e(q)
```

若 `H=⊥`、来源门失败、评价者未校准或分母无效，只做预先规定的时间漂移，不把未知变成证据。相同 `delivery_hash` 的重复评论只能计一次；同任务/同接收者相关重复不得当独立样本。输出 `P_v,c`、所用事件 ID、校准版本与不确定性；不改写 agent 的私有记忆或直接修改 workflow。校准频率若错、能力突变快于 `δ`、情境划分过粗或不同接收者误差相关，数值不是可靠后验。

后续 `W_t` 因实际任务出现一个类型为 `c` 的产出职责时，由**没有直接评价候选者**的合法 owner 在可通信邻居中选人。开发版本仅当所有候选在 `c` 都有至少两位不同真实接收者的有效事件时，按 `E_{P_v,c}[p]` 选最大；否则按预先固定种子的均匀探索。平局及探索概率固定、记录，产生真实执行和私有经历；`W_{t+1}` 仍由共同的正常 workflow 更新规则产生。第三方使用是检验可传播 `P` 与 owner 私有 `B` 是否真的有区别，不是第三方证言机制的新颖性主张。

```text
on_delivery(e):
    seal producer output → seal recipient pre-action judgment → allow action
    seal actual use / repair / legal public feedback and all costs
    h = derive_H_from_source_grounded_event(e)
    if h in {0,1} and calibrated(j,c) and authorized(e): update P[v,c] once
    else: record UNKNOWN/abstain, no evidence update
on_new_open_producer_duty(owner, c, W_t):
    candidates = legal_neighbors_with_same_permission(owner, c, W_t)
    if every candidate has cross-recipient support: select max posterior mean
    else: seeded uniform exploration
    seal assignment and propensity before any future execution/score
    run selected candidate; let all groups' common M/W dynamics proceed
```

## 手算例（纯示意，不是实验）

为便于手算，把网格缩为 `{0.25,0.75}`、各点先验 `0.5`，本两步设 `δ=0`。假设两位接收者 `B,D` 各自曾由合法抽审得到 `t=.8,f=.2`。产出者 `A` 的两份不同交付分别由 `B,D` 验收并实际使用，均为 `H=1`；产出者 `C` 的两份由同两人指出可核实的产出错误，均为 `H=0`。这是假设数据，不对应 AppWorld 已观察结果。

对于一次 `H=1`，`L(.25)=.35`、`L(.75)=.65`；两次后高点权重为 `.65²/(.35²+.65²)=.7752`，所以 `E[p_A]=.25×.2248+.75×.7752=.6376`。两次 `H=0` 对 `C` 给出高点权重 `.35²/(.65²+.35²)=.2248`，`E[p_C]=.3624`。未曾直接评价 `A/C` 的 owner `E` 若在之后的真实 workflow 中遇到相同情境、两人都合法可选且成本/权限相同，开发规则会选 `A`。若 `B,D` 的两个好评来自同一条交付的复制消息，只计一条而不能通过“两名接收者”门槛。

## 与强对照的精确等价和反证

**同信息 contextual bandit 可以精确模拟此算子。** 令其上下文包含 `c,W_t,候选集合,身份/合法通信、事件时序、成本和校准版本`，状态包含上面的网格分布与评价者频率，奖励观察为同一个 `H`，选择和更新使用同一式子；对相同历史和随机种子，它每一步得到相同的 `P`、同样的选择概率和同样的职责。把算子称作“role evidence”不能改变这个等价性。CADMAS-CTX 的固定 verifier 版、普通带接收者特征的 bandit、RAPS 的证言传播和 Meta-Team L2 都应得到**同样的原始事件、传播权限、存储与总预算**。若其中一个实现同式同策，预期差异为零，不能在论文里称该式子有独立方法增益。

它还有明确失败情形：接收者全量独立重做导致 `H=1` 却无交付边际价值；宽严不同且公开抽审不足导致误校准；只审可疑例造成 `t/f` 偏差；产出者被选择的任务更易或更难；多位评价者相互抄写；私有技能更新快于证据积累；当前 workflow 的职责语义变了仍沿用旧 `c`；真实依赖被 AppWorld 人工席位制造；评价/审计费用吃掉收益。C3 式重放若同预算提供更直接的责任估计，观测代理会失去理由。只见 posterior 变化而后续职责不变，也不构成角色形成。

## 最小真实数据开发试验与停机

1. **先完成已经独立设计的交付可见/隐藏 paired-dev 诊断**，不改其 runner/config。它只能问交付对同一接收者的边际效果，不能验角色算子。若预选多个不同家族中接收者独做质量不差、完整成本不高，停用 AppWorld 人工两席作为主科学环境。
2. 仅在交付有价值、真实 provider/合法观察链稳定后，另立预注册开发协议：至少两个从相同初态、经真实不同任务经历形成状态的可选身份，至少两位交叉评判的真实接收者，收费且对所有组开放的公开抽审校准，以及一个此前未直接评判候选者的第三方 owner。对各事件封存原始模型请求/响应、世界 I/O、交付逐项来源、行动前判断、实际使用/返工、任务/工作流版本、完整费用和失败。训练 `_1/_2` 与未来 `_3` sibling 只算相关开发例；已看过 scorer 的家族不能冒充独立确认。
3. 在未来交付与评分前封存 owner 的候选与概率，同时让同信息 contextual bandit、CADMAS-CTX 适配、Meta-Team L2、RAPS witness 适配、原始接受率和终局-only 在同等信息/通信/预算下影子决策；有分歧时才以独立重置的世界配对检查选择后果。主报告分别给未来交付公开盲审质量预测、官方任务成功和**含生产、接收、评价、校准、通信与选人的完整成本**；私有 scorer 只在行动封存后用于离线统计。多个独立长期流才能谈角色与 workflow 共演。
4. 任一门失败就记录并停在该门：真实链未封存、合法抽审不足或 `t≤f`，不作职责更新；选人与同信息强 bandit 完全一致，停止以该算子作为新方法的额外昂贵确认；未来收益只来自更强观察而非更新规则，应改述为**同伴行为是否是有用监督信号**的经验发现，并承认近期先例。任何正向小样本也只支持设计独立确认，不证明可中稿或创新已成立。
