# 原问题的创新边界：消费者判断、角色证据与责任

2026-09-23 的定向一手来源核查；它不是穷尽性新颖性证明。来源版本和 SHA256 见[本地索引](../../../references/aamas/peer_judgement_20260923/sources.json)。这里讨论的是**他人对交付的判断如何形成后续可用的角色证据**，不把 agent 与 workflow 的天然共生关系当作独立研究问题。

## 已被先例覆盖，不能据此主张创新

| 泛化主张 | 一手来源中的直接重合 |
|---|---|
| 下游同伴提供反馈、队友画像和角色/组织共同演化 | [Meta-Team §3.1–3.2](../../../references/aamas/acquisition_followup_20260922/metateam_v1.html)让 agent 交换其输出如何影响下游执行的证据，修改 teammate profiles，并可增删角色或调整组织。仅把评价者从统一 judge 改为同伴，不足以区别它。 |
| 按任务语境维护同伴能力并据此委派 | [CADMAS-CTX §3.3、§3.6](../../../references/aamas/peer_judgement_20260923/cadmas_ctx_v1.html)已有 agent-local、语境化 Beta 后验和风险感知委派；其更新信号是固定 judge/任务 verifier 的二元结果。任何新方法都应与给予同等观测的情境信任/上下文 bandit 比较。 |
| 交互形成同伴信誉并改变关系 | [RepuNet §3](../../../references/aamas/peer_judgement_20260923/repunet_v3.html)已有自我/同伴信誉及关系增删；其目标侧重合作困境，不等于交付正确性，但“信誉驱动网络演化”本身已有。 |
| 稀疏去中心网络中的直接评价、第三方证言、评价者可信度和动态角色 | [RAPS §§4.3–4.4, 5.5](../../../references/aamas/raps_20260923/raps_v1.html)已有本地 watchdog 对消息有用性的二元判断、证人信誉/间接证言的贝叶斯融合、信誉路由，以及从通用初态动态调整订阅/角色。[钉版本审查](../../../references/aamas/raps_20260923/README.md)说明其边界。单独增加第三方传播或稀疏图，不足以区别该先例。 |
| 贡献分数让角色检索、保留、删除发生变化 | [Sero §3.2–3.4](../../../references/aamas/peer_judgement_20260923/sero_v1.html)已有快信用、周期性 leave-one-out、历史 EMA、信用引导角色检索与受约束的角色编辑。 |
| 团队失败不能自动归责给正确的上游执行者 | [C3 §2.2](../../../references/aamas/peer_judgement_20260923/c3_v2.html)直接举“上游分析正确、下游引入错误、终局回报为零”的例子；§2.3、§3用固定历史下的动作干预估计逐决策优势，§7明确讨论故障责任与能力诊断。我们的 v4/v5 单例不能将这一认识写成首创。 |
| 把少量昂贵反事实重放用于校准便宜的贡献预测，并按预算分配重放 | [Marginal-Contribution Policy Gradients §4、§6.1、§7 式(20)–(22)](../../../references/aamas/causal_peer_role_20260923/marginal_contribution_pgma_v2.html)已有交互条件下的边际贡献、门控反馈的 propensity 校正及 `预测 + 抽样反事实残差/抽样概率` 的无偏校正与预算分配。[钉版本审查](../../../references/aamas/causal_peer_role_20260923/README.md)。若用接收者报告预测交付的边际价值、用随机可见/隐藏重放纠偏，不能仅据此称该公式新。 |
| 下游消费者以自己的接纳判断训练上游生产者 | [DAC §3.2、§3.4](../../../references/aamas/causal_peer_role_20260923/dac_v1.html)让实际下游 generator 的弃答判断连同外部证据充分性进入上游 searcher 奖励，并计算逐轮下游奖励差。它预置搜索/回答角色并训练 QA 模型，尚非本项目想要的跨工具任务角色形成；但“由下游判断监督上游”已非空白。 |
| 从旧轨迹提炼能力卡再决定委派给谁 | [DecisionBench §3–4](https://arxiv.org/html/2605.19099v1)已让池外双 LLM judge 离线读取候选模型的旧轨迹形成能力卡，随后由 orchestrator 选择 11 个异构模型之一。它没有公开实现实际接收者的结构化采用/返工驱动在线跨任务更新，但“先画像、后委派”已是近邻，不能作为独立创新。[固定版本代码与数据核查](../../../references/aamas/decisionbench_20260923/README.md)。 |

## 仍可检验的、更窄的研究问题

候选是：在真实的多步工具任务里，**实际消费交付的同伴**何时能够提供比终局分数、自评或固定 verifier 更早、更可用的角色证据？该证据至少要区分其行动前验收、实际使用与返工、生产者主张的可审计来源，以及后来可归因的失败；还要估计评价者自身误差和评估成本，再影响随后独立任务中的局部分工。RAPS 已覆盖第三方证言和证人可信度，Meta-Team 已覆盖下游反馈到同伴画像；因此这里每一项及其组合都是待实现/待验证条件，尚无已证明的新算子。

[唯一真实开发单例](AAMAS_PEER_JUDGMENT_PILOT_INTERPRETATION_20260923.md)正好暴露了问题：接收者验收并照提案成功创建三笔请求，官方终局却因接收者自己的 `complete_task` 格式失败；同时生产者的逐项来源引用也有漏洞。它证明四类证据不能混为一个标签，**没有证明**消费者判断更准确、能形成稳定角色，或能提高后续分工效果。接收者独立重读过资料，匹配提案不构成因果使用证据。

C3 是必须正视的强反例：如果环境状态可快照，固定历史反事实重放能给出更直接的责任估计。其论文的“精确恢复”论证明确假设可观测文本就是完整状态；我们的 AppWorld 外部工具状态需另行捕获或重放，成本和随机性应实测，不能笼统说 C3 不适用。若同预算重放可行且更准，所谓只靠消费者观测的路线需要退缩或放弃。

更尖锐的候选是把角色证据的目标改为“选择此生产者给当前接收者/工作流，比可执行替代方案增加多少任务质量、节省多少全系统成本”，而非交付内容正确率。`accept/use/repair` 只能作为这个目标的便宜、有噪声代理，不能直接充当因果标签；随机化或可快照的配对审计才可能校准它。但 [Marginal-Contribution Policy Gradients 的式(20)](../../../references/aamas/causal_peer_role_20260923/marginal_contribution_pgma_v2.html)已经覆盖最自然的代理加抽样审计校正式。其角色决策还可被同信息情境 bandit 表达。因此这只是**待反证的方法方向**，不是已锁创新点；若对照能复制更新与选人，应报告同伴行为是有用/无用监督信号，而非声称新算法成立。

最小可反驳比较：冻结独立的训练/确认任务与长期 agent 身份，把验收、实际使用/返工、来源审计、后续纠错分别消融；在**相同信息、相同 LLM 调用和复核预算**下对比终局-only、自评、二元验收、情境信任/bandit、Meta-Team 式协作反思、Sero 式角色信用、DecisionBench 式旧轨迹能力卡，以及可行预算内的 C3 式固定状态干预。评估两个独立终点：角色证据对下一次交付质量的预测校准，以及实际后续局部分工的成功率/成本。若简单模型可吸收全部增量，或这套证据不能改变后续决策，就不应声称新方法成立。
