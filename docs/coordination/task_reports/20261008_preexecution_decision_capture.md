# 执行前决策输入保存与恢复 — 2026-10-08

**已补齐一个可复现性缺口：新运行会在任务执行前保存实际选中对象、原始特征和所读证据；任务中断也不必事后重算。没有新增真实实验效果，科学投稿门保持关闭。**

## 目的与验收

上一轮主版维护完成了固定入口和源文件一致性核验，分类为进展。本轮回到方法标准 B、F.1/F.2：未来任务的反馈必须对应当时实际作出的选择，不能用后来变化的表示或经验库重建旧输入。

复用现有 SelectionSeal、DecisionSidecar、两类 offer 和消费证明，仅修复落盘缺口，不另造延迟奖励协议。验收指标：任务启动前保存；精确 candidate@version 与原向量可恢复；已保存文件不可被后续状态变化或重复保存覆盖；角色评价的实际评分投影不能丢失；原有诊断限制不退化。

## 改动与观察

- source 选择保存一次；各 target 在执行前保存自己的输入，并引用父 source capture 的摘要。后续选择预览不冒充实际执行。
- 保存完整 sidecar、反馈 offer、消费证明、原生/辅助记录前缀、注册表；使用角色评价时同时保存 role offer、实际评分投影及其读取关联。
- 重载既有类型并核对关联，返回保存的选中向量。当前运行器重载用于验证，尚未把它接入新的合法训练更新。
- target 执行身份直接取封存的精确候选 key，消除手工拼接 `@v1` 的版本隐患。
- C1 版本升至 v4；历史卡和结果不修改。测试临时卡显式使用当前代码版本，旧版本卡仍会拒绝。

## 失败、修复与证据

| 轮次 | 实际观察 | 解释与处理 |
|---|---|---|
| v1 | 37 通过、6 失败 | JSON 将 tuple 转为 list 导致独立前缀比较失败；角色测试随机选到无证据候选；旧测试卡与新版 runner 不匹配 |
| 独立审查 | 存在 role offer 时可删去 overlay，跳过评分投影检查 | 强制两者成对保存/恢复；补删除投影及版本错配反例 |
| v2 | 48 项定向检查通过 | 覆盖现有选择、消费证明、C1 诊断流程及新增恢复/中断边界；不是科学样本数 |
| v2 文件检查 | 4 个 capture 均止于选择记录；各自任务开始尚未进入前缀 | 1 个父 source、3 个 target；各保存 2 候选、64 维选中向量；这是软件夹具产物 |

根任务曾怀疑预创建目录与 actor 的 mkdir 冲突；阅读实际调用确认 actor 创建的是 judgment/action 子目录，该疑点被排除，没有据此修改执行语义。

角色测试改用固定、拥有证据的候选以检验序列化边界；这不是改变真实实验抽样。source 中断注入到运行器调用处；target 用例模拟保存后的任务开始前/后中断，未执行真实 API 故障注入。完整 C1 正常路径与已有 post-target 失败用例也通过本轮测试。

## 对 Goal 和三份标准的贡献

| 标准 | 本轮推进 | 仍缺什么 |
|---|---|---|
| 故事线与创新 | 避免用事后输入解释当时的分派 | 新训练机制、评价内容增量和未来分工收益均未证明 |
| 方法论 | 选择输入可恢复、版本与证据读取可核对 | 当前仍是身份 one-hot；任务/接收方语义、完整公开经验与合法后续收益尚未统一接入 |
| Benchmark + baseline | 对照运行可保留各自实际决策输入 | 完整同信息强基线、独立真实历史、确认集、完整成本和主结果未完成 |

role offer 存档包含 source outcome 等字段，但现有评分投影只读 source J；存档不等于消费全部字段。目标任务的未来 J/Y 不属于执行前输入。独立前缀核验依赖调用方提供独立账本；自洽摘要不是恶意修改防护或奖励许可。

本轮不修改 Goal、ACTIVE 方法或验收门，不把历史 C1 缺失向量回填成原始记录。论文源与唯一主版 PDF 未变，不为软件修复添加论文效果。
