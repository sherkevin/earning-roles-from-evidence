# PIPE2 v2 runtime field-gap audit — 2026-10-09

## Decision-relevant result

The native PIPE2 runtime receipt cannot yet be converted into a v2 typed
handoff descriptor. The receipt contains producer correctness and recipient
adoption evidence, but it does not contain the event-bound judgment/action/
outcome chain required by the responsibility protocol. The audit is therefore
**`FIELD_GAP_CONFIRMED`**, with **2 of 33** descriptor fields directly observed
and **31 missing**. This is an identification result, not a benchmark,
efficacy, or training result.

No API, candidate code, native grader, or GPU was invoked.

## What the receipt actually contains

The native receipt exposes `task_id`, producer status/label, producer artifact
digest, recipient self score, adoption status and digest, output digest,
source paths, and transport/adoption details. These observations are useful
for checking producer and adoption dimensions. They do not establish a typed
handoff identity or a causal responsibility chain.

The existing read-only replay reaches the same conclusion for all 40 control
rows: `REPLAY_QUALIFIED_UNKNOWN`, with zero labels and zero policy updates
(`experiments/logs/n03_pipe2_runtime_replay_20261003_v3/summary.json`).

## Required fields and their status

| v2 field group | Status in native receipt | Why it matters |
|---|---|---|
| `task_id` | present | Identifies PIPE2, but not an individual delivery. |
| `delivery_artifact_sha256` | present as nested producer/recipient digests | Useful evidence, but not bound to a delivery event or typed path. |
| `delivery_id`, path, schema | absent | A digest alone cannot identify which handoff event was observed. |
| candidate/version and source/contract digests | absent | Control names and source paths are insufficient for immutable candidate lineage. |
| recipient before/after manifests and changed paths | absent | Cannot distinguish recipient repair from producer defect or unrelated edits. |
| recipient `judgment` | absent | `recipient_self` is a scorer result, not the recipient's judgment about the delivery. |
| consumer `action` / `used_artifact` | absent | Adoption status is not a recorded downstream action. |
| independent terminal `outcome_status` | absent | Output digest/adoption is not an independently executed later outcome. |
| event indices, IDs, and record hashes | absent | No native ordering or cryptographic binding for delivery → judgment → action → outcome. |
| later assignment, read cut, observation availability | absent | No delayed-credit or future-selection update can be identified. |
| policy/credit flags and descriptor digest | absent | These are safe outputs of a validated descriptor, not facts in the old receipt. |

The following values are explicitly **non-substitutable** and must remain
missing until the runner records them: `judgment`, `action`, `used_artifact`,
`outcome_status`, all J/A/Y IDs and record hashes, and `target_task_index`.
Filling them from `recipient_self`, adoption, `output_sha256`, or producer
label would manufacture the causal evidence that the benchmark is supposed to
measure.

## Consequence for the paper and benchmark gate

The v2 descriptor remains a qualified candidate adapter, but PIPE2 is not an
active benchmark route. The current result supports one narrow statement in
the methods/limitations record: the existing runtime instrumentation is
insufficient for learning roles from situated judgments. It does not support a
role-learning result, a baseline comparison, a selector update, or an A800
run. The canonical paper remains unchanged; the master PDF is still the
internal revision recorded by `artifacts/aamas2027/main_pdf_master.json`.

## Minimum next experiment card

Before any new inference or GPU job, a single bounded real episode must record
the following in the native ledger, then pass v2 validation and replay:

1. a versioned candidate key, source/contract digests, and a unique delivery
   event with its artifact path/schema/hash;
2. a recipient-produced judgment event that can disagree with its later
   action, preserving the raw response and event hash;
3. a consumer action event with explicit `used_artifact` and recipient
   pre/post manifests over declared recipient-owned paths;
4. an independently run terminal outcome event, bound to the same delivery;
5. a later assignment and next-selection event before any policy update;
6. a same-information count-only or J-masked control, so any selector gain is
   not explained by extra context or by simply replaying the judgment;
7. raw JSONL, source snapshots, hashes, API usage, and failure records before
   the episode is considered complete.

The episode must stop with `UNKNOWN` and no update if any one of these records
is missing or cannot be replayed. This keeps the goal and scientific gate
unchanged while making the next action concrete.

## Independent review

An independent methods audit reached the same P0 conclusion: without native
J/A/Y events the current 40 `UNKNOWN` rows cannot identify role-learning
benefit. It also flagged two controls that belong on the next card: a
same-information J-masked/count-only control and an explicit read-cut check to
prevent future-outcome leakage. These are added as acceptance conditions, not
as post-hoc analysis choices.
