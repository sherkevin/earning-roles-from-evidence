# 公开上下文接线与可加表示反例 — 2026-10-08

**本轮把真实本地模型编码的任务/接收方公开合同接入现有选择记录，并证明一个需要留作对照的限制：分别编码再线性相加，表达不了某些任务–接收方互补。仍没有新增任务效果证据。**

## 目的与范围

上一轮执行前保存属于进展；本轮针对方法标准 F.1 的任务泛化输入。先由两个Codex分别审查现有接口与数学需求，确认旧history/profile只有摘要而没有充分的历史语义上下文，不能据此声称相似任务匹配。复用现有选择接口、捕获函数和已缓存BGE，不增加模型筛选、LLM调用或GPU作业。

验收是完整输入覆盖、同次决策绑定、保存恢复一致及不越权声称历史/能力效果。公开性来自明确选取已准备请求中的公开字段；纯文本函数不能保证调用方没有把私有信息塞入文本。

## 实现与结果

新增纯函数分别编码两段公开合同，float64归一化后等权拼为768维；身份、声明版本和read cut保留为元数据。超长在encode之前拒绝。恢复要求调用者提供选择时独立封存的上下文摘要，阻止相同接收方/read cut下误取另一任务的自洽记录。

| 检查 | 结果 | 可得结论 |
|---|---|---|
| 定向软件检查 | 54项通过 | 输入边界、数值组件与捕获接口未发现定向回归；不是科学样本数 |
| 实际本地BGE CPU编码 | 463与66 token，均未超过512；实际attention-mask计数一致 | 这两段公开文本没有静默截断 |
| 编码结果 | 768维；单次两段编码约0.167秒 | 一次设备观测，不是延迟分布或实时性结论 |
| 现有选择与恢复 | 原向量、上下文摘要、精确候选绑定一致 | 可以把该候选输入放入现有执行前记录 |
| 未训练对照 | 两候选分数均0、概率均0.5、0更新 | 没有训练收益或匹配质量结论 |
| 数组状态 | 两个768维ridge状态合计9,461,760字节 | 仅数组，不含模型/进程/存储，不是完整系统内存 |

接收方语义输入只有公开职责；processor.py摘要作为声明版本，源码本身未编码。未读取过去评价作为特征；不将此结果命名为完整同信息基线。示例候选注册和选择流程是软件夹具；只有编码计算使用真实冻结本地模型，未执行Agent任务。

## 方法审查的实际影响

[候选说明与逐式实例](../../research/candidates/public_context_representation_v0.1_20261008.md)给出可加得分恒等式及互补反例。即使每个Agent有自己的任务权重，任务项与接收方项简单相加仍不能覆盖全部情境关系。后续应保留该模型作为对照，先在合适数据上检验互补需求，再决定联合表示或交互；本轮不冻结或推翻 ACTIVE 主方法。

独立审查要求把全文摘要绑定到选择，已实现并由真实本地向量走通。摘要只作可信运行器内的一致性检查，不是外部真实性签名。旧记录不补写为历史输入。
