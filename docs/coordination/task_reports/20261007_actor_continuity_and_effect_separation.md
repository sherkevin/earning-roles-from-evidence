## 目的、衡量标准与实际发现

本轮目的不是继续增加历史容器测试，而是找到“有状态 peer”的真实执行缺口。
通过标准是：代码调用链可定位、源/状态/产物身份不混淆、收益对照能辨别归因、
已发表做法与本论文所需贡献区分。没有要求模型结果变好，也没有开展效果实验。

## 辩论中保留的修正

1. 初议先测个人历史、再测选择器、最后共同变化。独立审查指出：单项不显著不排除
   交互；修订为只按结构性缺失停卡，小 pilot 的零差异一律 `INCONCLUSIVE`。
2. 两 peer × 历史显示/遮蔽可以诊断自然差异，却取得未选路由结果。修订为独立
   operator 账；所有额外调用计研发成本，不能用于线上 selected-only 更新。
3. 个人经历变化不应逐轮创建“新 Agent”；修订为生成策略/模型/模板版本固定，
   历史摘要与实际产物摘要分开记录。旧 C1 的静态语义不回写。
4. 最后审查又区分两个“四格”：两人×目标历史输入是固定样本诊断；记忆×选择器
   是未来在线制度实验。前者不能估计后者的均值/区间。在线历史还会通过 J 改变
   分派，因此分解只能叫系统制度效应，不能冒充纯 actor/selector 因果路径。
5. 新目标不能仅换 seed 就宣称泛化。源/目标须事前标明样本、规则、域、root 的
   重叠；合法规则复用不是泄漏，但不等于新规则或跨 root 迁移。

## 与 Goal 和三份标准的差距

- **故事线**：明确最终要解释的是未来责任分派和团队收益。个人经验可以是共同
  基座，但不能取代“从他人消费评价中学习角色”的创新。
- **方法论**：确定可复用的身份/状态/交付接口，以及不能混算的收益路径。真正
  producer 持久经历、完整合法 reward、自己的在线训练方法仍未完成。
- **Benchmark + baseline**：新增能区分个人改善与选人改善的设计；仍缺任务与
  split/成本/预算冻结、两个 root、同信息真实基线和独立确认效果。

本轮0次模型 API、0次候选/评分器/生成器执行、0次 GPU。三份标准均未通过，投稿
gate 保持关闭。没有改正文、没有新增效果数字，也没有与并行图稿任务争用文件。
