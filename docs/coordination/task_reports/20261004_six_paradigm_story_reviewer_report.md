## 2. 与六大叙事范式的对应

### 主范式：①根因手术刀

当前最清楚的根因是：

> The same collaboration feedback can be generated by a producer defect or recipient-owned integration, so it cannot identify which agent should receive the next responsibility.

Intro 第一段的两个 constructed queue-processing cases 把这个根因具体化；第二段明确命名为 `responsibility ambiguity`；第三段给出 sharp question；方法随后建立 responsibility boundary。该链条已经符合“先解释为什么现有方法翻车，再提出解药”的范式。

仍需统一 `responsibility ambiguity`、`responsibility confounding`、`attribution failure` 三个词。建议把 `responsibility confounding` 作为根因术语，把 ambiguity 作为观察到的后果，把 attribution gate 作为机制响应。

### 辅助范式：②反直觉重构

当前稿件清楚挑战了一个默认设定：

> acceptance/rejection 或 terminal reward 不是天然的 producer quality label。

反直觉点不是“recipient 一定更可靠”，而是“recipient 是最接近 artifact 的观察者，同时也可能把自己的 integration 困难带入判断”。这为责任 gate 提供了必要性，而不是装饰性的故事 hook。

### 辅助范式：④新基准暴露失效

摘要和 Introduction 现在把 ArtifactRole 写成 candidate track，并没有声称 benchmark 已冻结，这是正确的。当前文章还没有足够证据把它写成“已暴露系统性失效”的成熟 benchmark。真实 priority audit 可作为 diagnostic motivation，但不能替代跨 root、独立 streams 和 baseline result。

### 辅助范式：③理论照亮经验

方法中的 read-cut、sealed assignment、delayed selected-only credit 与 replay 可形成 I1–I3 不变量，但当前正文仍使用 `make ... testable` 和 `properties to measure`，没有把工程资格写成定理。这是正确的证据边界。若要使用③作为强叙事，后续至少要给出形式化假设、命题和 machine-checkable proof/replay receipt。

⑥极简统一美学可作为次要风格目标，但当前协议仍有较多审计字段，不宜把“字段多”包装成极简算法。⑤社会价值不是当前中心范式。

## 3. 摘要五句审查

当前摘要五句的功能为：

1. **问题/后果**：多智能体需要在不知道 collaborator 是否能让 dependency usable 之前分派 responsibility，downstream failure 又混合 producer defect 与 recipient integration。
2. **现有方法限制**：reputation、acceptance 和 terminal reward 无法区分 producer evidence 与 recipient difficulty。
3. **机制**：versioned delivery → observable use → ownership gate → evidence publication → future assignment → delayed selected-only credit。
4. **可证伪预测**：只有在 matched information/candidate/cost 下，situated evidence 提供 acceptance/terminal 之外的 producer-attributable information，才应改善 unseen responsibility assignment。
5. **范围/实验合同**：形式化 event/read-cut，定义 ArtifactRole/PeerSelect、baseline、root split、latency/forgetting/attribution/cost measures，并排除 universal expertise 等强主张。

这比之前的 pre-results 摘要明显更接近正式论文风格。当前没有以下违规：

- 没有宣称显著提升；
- 没有宣称已经实时训练；
- 没有宣称已形成专业化或 universal reputation；
- 没有把 zero-call qualification 写成方法效果。

### 摘要仍需注意的句子

> `Existing reputation, acceptance, and terminal-reward schemes collapse these sources...`

这是一个较宽的领域判断，正式版本需要在 Related Work 中给出最近邻的输入、更新时间和 credit semantics 证据；否则可收窄为：

> `In dependency-bearing workflows, reputation, acceptance, and terminal-reward signals can collapse these sources...`

> `We formalize the event and read-cut boundaries and define ArtifactRole and PeerSelect tracks...`

当前是设计性贡献，尚不是 benchmark result。若正式摘要在 benchmark 冻结前提交，应改为 `pre-register candidate tracks` 或保留 `define candidate tracks`，避免读者理解为 benchmark 已获权威确认。

## 4. Introduction 逐段审查

### 第 1 段：双构造性反例

当前段落先提出问题，再给出两个构造案例：同样 rejection 和 failed team outcome，分别由 producer contract defect 或 recipient integration defect 产生。这是当前最强的 narrative hook。

优点：

- 明确 multi-agent dependency；
- 给出最小不可识别性反例；
- 没有把构造案例伪装成真实实验统计；
- 直接解释为什么 raw acceptance/terminal reward 不够。

可选的措辞优化：为了满足 v1.3 “现象先于反例”的行为顺序，可以把第一句改为：

> `In dependency-bearing multi-agent workflows, a collaborator's value is observed through another agent's attempt to use its artifact.`

然后再接 `How can collaborators earn...`。当前写法不构成 hard fail，但从 AAMAS 行文看，先给协作现象再给研究问题会更自然。

### 第 2 段：根因命名与边界

`This example isolates responsibility ambiguity` 清楚地把构造案例提升为研究问题。`A later outcome can inform subsequent decisions; it cannot retrospectively alter...` 正确表达了 event-time boundary。

仍需把 `responsibility ambiguity` 与全篇唯一根因术语统一。建议改为：

> `This example isolates responsibility confounding: the same feedback can describe producer correctness, recipient integration, or neither.`

然后把 `ambiguity` 留作现象描述。

### 第 3 段：sharp question 与主链

当前问题句明确包含 recipient、delivery、producer responsibility 和 future use；公式给出完整链条：

```text
delivery → recipient use/judgment → producer attribution
→ future assignment → unseen quality/cost
```

随后四个短句分别排除 final score、acceptance、recipient normal work 和不改变 pre-execution assignment 的 role posterior。这些句子为方法的四个必要边界提供输入，逻辑非常清楚。

### 第 4 段：机制

`public, version-bound evidence object with a responsibility boundary` 是一个明确的唯一机制对象。后续 gate、read cut、assignment seal 和 delayed update 应被理解为该对象的合法性约束，而不是多个并列创新。

`makes the separation observable in the ledger` 是协议级陈述，可以保留；不能在没有 live evidence 时改成“guarantees correct attribution”。

### 第 5 段：命名与创新边界

当前写法比旧稿更好：`Earning roles` 描述动态责任机会，RARE 被定义为 judgment–attribution–assignment loop，而不是某个 representation、RLS 或 refit。它体现了动态/自进化方向，但没有提前声称已经产生 self-evolution。

建议把 `We call the protocol's implementation responsibility-aware role evidence (RARE)` 改成：

> `We call this responsibility-aware role evidence (RARE); the name refers to the loop's evidence semantics, not to a particular updater.`

原因是当前 RARE 更像方法语义对象，不只是“协议的 implementation”。

### 第 6 段：贡献列表

四项贡献都使用设计/协议层级措辞，未伪造结果。它们能映射到 Problem Formulation、Method、Benchmark 和 Falsification sections。

需要注意：

- “candidate ArtifactRole track”已正确限定；
- PeerSelect 已写成 secondary mechanism track，主次关系清楚；
- “testable noninterference and idempotent replay”是可检验性质，不是已证明性质；
- 正式稿仍应增加 novelty table，至少比较五个最近邻的输入、更新时间、责任/credit semantics 和实验对象。

### Figure 1 后的证据边界与路线图

当前段落：

> `The present evidence boundary is deliberate...`

比旧稿的 `current scientific release gate is closed` 更适合论文，但仍然是 internal pre-results 语气。作为内部稿可以保留；正式投稿必须改成实际结果和范围解释。

该段还提供了路线图：gap → event contract → protocol/baselines → RQs/matrix → current evidence/limits。满足 v1.3 对引言路线图的要求。

## 5. 方法章节与命名

### 方法章节标题

当前标题：

> `Earning Roles: A Responsibility-Aware Protocol`

比 `Candidate Mechanism: Earning Roles` 更符合会议论文风格，也避免把尚未选定的 backbone/updater 冒充科学贡献。标题明确了方法对象是 protocol，RARE 的科学对象是 evidence semantics。

### 方法叙事顺序

当前顺序基本符合 v1.3：

```text
objects/information boundary
→ responsibility gate
→ interfaces/timeline
→ representation/score
→ properties and innovation boundary
```

仍需保持以下语言边界：

- `The protocol has two independent interfaces`：协议定义；
- `The score is a contract-level construction`：候选实现；
- `These are properties to measure`：实验预测；
- 不能把 RARE-Anchor、hash64、RLS 或 periodic refit 写成已选择的 final backbone。

## 6. 内部草稿语气与 AAMAS 风格

当前正文仍有以下内部稿标记：

- `% Internal pre-results manuscript. Empirical cells are intentionally blank.`
- `\acmSubmissionID{INTERNAL PRE-RESULTS -- NOT FOR SUBMISSION}`
- `\affiliation{Internal research draft}`

这些内容对研究过程记录是正确的，不能出现在最终投稿稿中。当前正文的摘要和 Introduction 已经基本避免了 defensive meta-language，保留这些标记只说明它仍是内部草稿，不是叙事失败。

正式稿需要替换为：

- 真实的实验结果和 uncertainty intervals；
- benchmark 的最终名称、manifest 和根 split；
- 图注中的方法语义和实证观察；
- 去除 internal/release-gate/empty-cell 说明；
- 将“当前证据边界”改为结果解释和局限。

## 8. 最终判断

当前稿件的文字结构已经达到“可继续打磨”的阶段：

```text
协作现象
→ 双构造性失败
→ responsibility ambiguity/confounding
→ sharp question
→ responsibility-scoped evidence
→ sealed future assignment
→ delayed credit
→ 可证伪预测与 falsification boundary
```

这条链符合六范式中的根因手术刀，并用反直觉的责任标签失效增强 hook。摘要五句功能完整，Introduction 已有贡献、范围和路线图，方法标题与机制对象也已收敛。

但论文距离三份标准的 Proceedings-ready 仍有实质距离。当前可支持的是协议级/工程级叙述；信号级、闭环级和泛化级主张仍 OPEN。正式投稿前不能把空结果矩阵、单 root 工程资格或内部 diagnostic 变成方法效果。

### 10.3 Must-fix issues

#### P0 — bandit citation and description are too broad

The row

> `Contextual trust / bandit \cite{auer2002finite}`

claims context, selected feedback, propensity and arrival delay, but `Auer et al. (2002)` is the classical finite-time multi-armed bandit analysis and does not by itself establish contextual features, propensity logging, or delayed feedback. This is a factual mismatch in the novelty table.

Choose one of two repairs before submission:

1. Rename the row `Classical bandit / selected-reward control`, restrict the observed signal to selected reward and online score update, and state that context, arrival order and responsibility semantics are introduced by the present adapter; or
2. Keep `Contextual trust / bandit`, but add a primary contextual-bandit and, if delay is claimed, delayed-feedback source, and update the row to describe exactly what those papers implement.

Do not use the Auer citation as evidence for all three properties.

#### P1 — five families are not yet five named nearest neighbors

The v1.3 hard gate requests at least five nearest neighbors with their problem, input, update rule, credit semantics, experimental object, and true difference. The current table has five *families*, with multiple papers grouped into several rows. This is a useful first pass, but a strict reviewer could say that no individual nearest method is actually compared end-to-end.

Recommended repair:

- either name one representative paper/system in each row and add an explicit `Problem/objective` column;
- or add a short second table in supplementary material mapping every family row to one named method, its exact input, update, credit object, and limitation.

The current `Boundary tested here` column is close to a difference column, but renaming it to `Difference / test in this paper` would make the contract explicit.

#### P1 — qualify negative claims about prior systems

Phrases such as:

> `source and sink work are not separated`

> `attribution to a producer artifact is unspecified`

are plausible distinctions, but they read as definitive claims about cited systems. Unless the source papers explicitly document the absence, use narrower wording:

> `the cited formulation does not expose a producer–recipient artifact ownership contract`

or:

> `the paper evaluates role/expert utility without an explicit producer-artifact attribution field in the reported protocol.`

This keeps the comparison grounded in the papers' observable interfaces rather than claiming that an implementation cannot support the distinction.

#### P2 — keep the bridge tied to the one gap

The bridge paragraph is currently focused. Preserve its final sentence about delayed contextual learning as an alternative explanation. Do not add additional families merely for coverage; every added row must explain why it cannot identify producer responsibility under the same observation, timing and credit contract.

## 11. Related Work 最终文字复核：具名近邻与 bandit 修订

**审查结论：表格组织通过；仍需两处文字修正。** 本轮没有修改正文、运行实验或重新核验近邻全文，因此这里的通过只涉及叙事结构和当前文字的一致性，不代表 novelty 的科学验收通过，也不重新认证七页排版。

### 已关闭的问题

- 表格现在给出具名论文/系统，并以 observation/update、credit、experimental object、difference/test 比较。相比只列家族，读者能追溯到实际近邻。

- 其他行使用 `the cited formulation(s)` 限定比较对象，避免声称整个研究方向不可能实现某种能力。
- 表格与正文的责任混淆主线一致；没有通过新增文献引入另一个中心问题。

### 仍须修改的两处

**P1：Related Work 末段仍把 delayed feedback 等同于时间泄漏。**

当前句子：

> Updating the source producer from the later outcome would leak future information and conflate source and target responsibility.

在 outcome 到达之后更新状态、仅供更晚的决策使用，是合法的在线学习。是否归因错误与是否时间泄漏是两个问题，不能一概而论。这一旧句也与 Introduction 已修正的时间语义不一致。

建议替换为：

> A target outcome may update later decisions once it arrives. Using it to reconstruct an earlier assignment would violate that assignment's information boundary; treating it as a label of the source artifact would also require a separate attribution argument.

这保留本协议的严格责任语义，同时不把普通 delayed learning 错写成天然泄漏，也不以这条不正确的对比制造新颖性。

**P1：Auer 行的最后一格仍把原生非上下文方法直接叫作 same-information comparator。**

当前 `Difference / test here` 写：

> Same-information comparator with matched budget and cost

它与同一行声明的原生输入范围不完全一致。建议写：

> Classical selected-reward control; contextual and delayed adapters require separate qualification.

同时可将 credit 列精简为 `Arm-level reward; no producer–recipient ownership contract`，无需新增 `no propensity` 这一与中心差异无关、且容易因原论文具体策略定义引发争议的否定断言。
