# 故事线评价标准 v1.0

- **状态**：`ACTIVE`
- **评价对象**：[`storyline_v1.0_20260928.md`](../../storyline/storyline_v1.0_20260928.md)
- **用途**：判断故事是否足够 sharp、自洽、可被 AAMAS 审稿人检验；不是结果报告。

## 必须通过

1. 一句话问题包含真实依赖、recipient situated judgment、producer role evidence、future assignment 和未见任务质量/成本。
2. 交付、判断、recipient action、producer contract、later outcome、UNKNOWN 和成本分别可观察。
3. 主创新只有一个：责任感知的 situated judgment→role evidence；能力学习、workflow 搜索、信誉传播等不能同时冒充独立创新。
4. 公共角色证据 `P_v(c)` 与 owner 私有信任 `B_u(v,c)` 分开；未来 owner 至少有机会使用合法传播记录。
5. 明确哪些结果会反驳主张；失败不会自动收窄 Goal。
6. 标题、摘要和结论不能超出当前证据。

## 审稿红线

预设专家身份、脚本指定角色、只用 detached judge、自评、acceptance rate、单次终局成功、没有 future assignment、没有独立 later-use 或把 consumer 自己的 integration 归责给 producer，均不能支撑完整 role formation 故事。

## 通过证据

至少需要两个结构 root 的独立 stream、可审计责任链、第三方/非直接评价 owner 的未来选择、同信息强 baseline 和完整质量—成本结果。只有协议/fixture 通过时，评价结论必须写成工程资格，不得写成科学效果。
