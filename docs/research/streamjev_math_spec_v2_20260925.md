# Stream-JEV 数学问题：严格记号版

**日期：** 2026-09-25  
**用途：** 作为 peer/tool selection 的统一数学定义；不指定 backbone，也不指定更新算法。

**范围：** 本文是第一阶段可执行的单步 CDS-CB 子问题。若选择动作会改变未来
协作状态，完整故事采用 [`earning_roles_controlled_process_model_20260925.md`](earning_roles_controlled_process_model_20260925.md)
中的受约束控制过程；不能把单步 bandit 误写成完整 peer-role 数学定义。

之前的定义把“决策时刻”和“反馈到达时刻”混在了一起，容易把未来标签误当成当前可用信息。本文只保留一个离散决策流，并显式区分两个索引。

一个具体例子：第 `5` 次选择选了候选 `a`，执行需要 `D_5=3` 个 tick 才能判断正确性，所以 `τ_5=8`。第 `5` 到第 `7` 次选择都不能使用这条标签；标签在第 `8` 次动作完成后进入 `B_8`，并从第 `9` 次选择开始影响策略。这个例子中，`5` 是“动作发生的时间”，`8` 是“标签可用的时间”。

## 1. 两个时间索引

- `t = 1,2,…`：第 `t` 次选择发生的**决策索引**。
- `k = 1,2,…`：反馈被系统收到并可以用于更新的**到达索引**。

第 `t` 次选择产生的反馈不一定在同一时刻到达。令 `D_t ≥ 0` 为延迟，并定义

```text
τ_t = t + D_t
```

为该反馈的到达索引。约定：动作 `A_t` 先做出，`τ_t=t` 的反馈在本次动作之后处理，因此它不会影响自己的选择，只会影响后续选择。

在到达索引 `k` 收到的事件集合为

```text
B_k = { e_t : τ_t = k }.
```

`t` 描述“这次选择何时发生”，`τ_t` 描述“这次选择的标签何时可用”。任何训练或更新规则都只能读取已经到达的 `B_k`。

例如：第 5 次决策选择了 `A₅`，延迟 `D₅=3`，所以 `τ₅=8`。第 5、6、7 次决策
都看不到 `Y₅`；第 8 次动作结束后，事件 `e₅` 才进入 `B₈`；第 9 次决策才能
使用这条反馈更新后的状态。这个例子固定了“延迟标签不能影响产生它的动作”的语义。

本文采用统一的 **end-of-tick** 约定：第 `t` 次动作先依据 `F_t,S_t` 产生；本 tick 结束时把 `B_t` 交给更新器，得到下一次动作使用的 `S_{t+1}`。这避免了“同一条即时反馈既影响当前动作又影响下一动作”的循环定义。

## 2. 一次决策的随机变量

发起选择的 agent 记为 `i_t`。若是 peer selection，候选集合由局部图产生；若是 tool selection，候选集合是普通候选池。

### 2.1 决策输入

```text
X_t        任务上下文和工作流状态
C_t        当前可选候选集合
c ∈ C_t    候选，包含 (id, version, metadata)
V_t(c)     候选 c 在决策时的版本
G_t        可选的 peer 图；tool selection 时可省略
```

peer selection 的最小映射是 `C_t = N_{G_t}(i_t)`（也可再施加可用性过滤）；tool selection 直接给定 `C_t`。因此图结构只负责生成候选集合，除非额外证明图消息传递改善 `H_t`，否则不应自动把整个问题写成 GNN 问题。

候选换版本后视为新的候选对象。旧版本的反馈不能静默写入新版本。

### 2.2 潜在结果与实际观测

对每个候选 `c∈C_t`，定义一个潜在结果 `Y_t(c)`。它表示如果此时执行 `c`，最终会得到的二值正确性或质量标签。实际只执行一个候选：

```text
A_t ~ π_t(· | X_t, C_t, S_t)
Y_t  = Y_t(A_t)
```

其中 `Y_t(c)` 对未选候选不可见。若标签有噪声，定义其条件期望为

```text
r_t(c) = E[ Y_t(c) | F_t, X_t, C_t ] ∈ [0,1].
```

`r_t(c)` 是候选在该任务上的潜在期望效用；`Y_t` 是一次实际执行得到的样本。二者不能混写。二值正确性时，`Y_t∈{0,1}`；多值质量时可令 `Y_t∈[0,1]`。

如果执行后会立即产生可供下一动作使用的原始输出，另记为 `O_t = output(A_t)`。
`O_t` 是即时观测，`Y_t` 是延迟到达的正确性或质量标签，两者不能混为一谈。
当前 earning-roles 主问题是一轮一个候选，暂不使用 `O_t` 决定同一任务内的下一
个动作；如果以后加入复核或多次调用，应将历史扩展为 `H_{t+1}=T(H_t,A_t,O_t)`，
但仍然只在 `τ_t` 到达后把 `Y_t` 交给在线更新器。

## 3. 信息边界、策略和 propensity

令 `F_t` 表示第 `t` 次选择前系统能看到的全部信息：历史上下文、历史动作、候选集合、随机数，以及所有已经到达的反馈 `e_j`（即 `τ_j<t`）。它不包含未到达的 `Y_j`，也不包含未执行候选的事后真值。

在线状态记为 `S_t`，它是所有已处理反馈和共享模型参数的压缩结果。策略必须是 `F_t` 可测的：

```text
π_t(c) = P(A_t=c | F_t, X_t, C_t, S_t),  c∈C_t
p_t = π_t(A_t)                                             (实际 propensity)
```

其中 `p_t` 必须写进事件日志。为保证 selected-only 数据可识别，探索约束通常为

```text
π_t(c) ≥ p_min > 0,  对所有当时可选的 c∈C_t。
```

这要求 `p_min ≤ 1/|C_t|`；候选数变化时应明确使用固定下界、按菜单大小缩放的下界，或只对满足覆盖条件的候选评估。若某个候选的概率始终为 0，就无法仅凭 selected-only 日志估计它的质量。

## 4. 特征快照、事件和状态转移

决策时为每个候选计算表示：

```text
H_t(c) = E_φ(X_t, C_t, c; V_t(c), M_t),  c∈C_t
```

`M_t` 是当时的模型/特征协议版本。`E_φ` 可以是文本 encoder、set encoder、GNN 或结构化特征；本文不预设具体 backbone。

选中候选的事件记录为

```text
e_t = (
  t, i_t, X_t, C_t, A_t, p_t,
  H_t(A_t), V_t(A_t), M_t,
  τ_t, Y_t
).
```

在 `τ_t` 之前，事件中只有前半部分；`Y_t` 只能在到达时填入。事件必须绑定决策时的特征和候选版本，不能到达后再用新模型重编码。

令 `S_t` 表示做出第 `t` 次选择之前的状态。到达索引 `k` 的反馈先形成 `B_k`，再用于后续状态：

```text
S_{k+1} = U_ψ(S_k, B_k),
```

其中 `U_ψ` 只能使用 `B_k` 中已到达的事件。若 `D_t=0`，该事件在动作之后进入 `B_t`，所以影响 `S_{t+1}`，不影响 `A_t`。

等价地，`S_t` 只依赖 `B_1,…,B_{t-1}`；它绝不能依赖 `B_t,B_{t+1},…`。这条因果关系是后续实现和数据检查的硬约束。

`U_ψ` 需要明确乱序语义：要么把事件转换成可交换、可结合的充分统计量；要么保存事件并按决策时间重放。仅仅把事件放进 FIFO 队列不等于解决了乱序反馈。

## 5. 评价指标

### 5.1 Prequential utility

算法 `A=(E_φ, scorer, π, U_ψ)` 在真实在线流上的有限窗口效用为

```text
J_T(A) = (1/T) E[ Σ_{t=1}^T Y_t ]
       = (1/T) E[ Σ_{t=1}^T r_t(A_t) ].
```

这里的期望同时覆盖任务流、潜在结果和策略随机性。不能把未来标签提前用于更新；它们只在到达后进入 `B_k`。

### 5.2 Dynamic regret

离线 benchmark 若能提供每个候选的潜在期望效用，可定义当步 oracle：

```text
c_t* ∈ argmax_{c∈C_t} r_t(c)
Reg_T(A) = E[ Σ_{t=1}^T ( r_t(c_t*) - r_t(A_t) ) ].
```

训练时不需要也不能访问 `c_t*`；它只用于独立评估。若只有 selected-only 日志，应使用记录的 propensity 做 IPS/DR 估计，而不能直接把未选候选的真值塞进训练流：

```text
Ĵ_IPS(π_eval) = (1/T) Σ_t
   [ π_eval,t(A_t | F_t) / p_t ] · Y_t.
```

### 5.3 漂移后的适应速度

设 `ν` 是环境或任务分布发生变化的时刻，定义达到新 oracle 水平 `α` 的恢复时间：

```text
T_rec(α) = min{ h≥1 :
  (1/h) Σ_{j=1}^h r_{ν+j}(A_{ν+j})
  ≥ α · (1/h) Σ_{j=1}^h r_{ν+j}(c*_{ν+j}) }.
```

也可以报告漂移后固定窗口的 cumulative regret；必须预先固定窗口和 `α`，不能事后挑选有利区间。

### 5.4 旧能力遗忘

准备一份冻结的旧分布 holdout `D_old`，定义状态 `S` 在该 holdout 上的选择效用为 `Q_old(S)`。若 `S_ref` 是发布前状态，则时刻 `t` 的遗忘量为

```text
F_t = [ Q_old(S_ref) - Q_old(S_t) ]_+
F_peak = max_t F_t.
```

没有锁定的 `D_old`，只能说“参数变化较小”，不能声称“旧能力没有遗忘”。

### 5.5 实时和内存约束

```text
L_t^upd  = feedback receipt → updated state ready 的墙钟延迟
L_t^dec  = decision input → action emitted 的墙钟延迟
M_t      = 在线状态和事件缓冲占用的字节数
```

目标约束应写成真实服务测量的分位数：

```text
quantile_0.95(L^upd) ≤ B_upd
quantile_0.95(L^dec) ≤ B_dec
max_t M_t ≤ B_mem
F_peak ≤ ε_old
```

## 6. 完整优化问题

在所有满足因果性、selected-only、版本绑定和探索约束的算法集合 `𝒜` 中，目标是

```text
maximize_A        J_T(A)  或其长期极限 liminf_{T→∞} J_T(A)
subject to        F_peak(A) ≤ ε_old
                  q95(L^upd(A)) ≤ B_upd
                  q95(L^dec(A)) ≤ B_dec
                  max_t M_t(A) ≤ B_mem
                  π_t(c) ≥ p_min  (所有 eligible c)
                  U_ψ 只读取已到达的 selected-only 事件
```

因此“实时训练”不是单独的准确率目标，而是一个带实时、内存和遗忘约束的在线策略学习问题。

## 7. 如果学习新的更新算子

把一条训练流 `ξ` 切成 support 前缀 `P` 和 query 后缀 `Q`。`U_ψ` 在 `P` 中严格按真实到达顺序运行，只能使用 `B_k`；`Q` 只用于评估经过更新后的未来策略：

```text
ψ* = argmin_ψ E_ξ[
       - J_Q(ψ)
       + λ_F F_peak(ψ; D_old)
       + λ_L q95(L^upd_ψ)
       + λ_M max_t M_t(ψ)
     ].
```

这与“拿当前标签做一次普通监督梯度下降”不同：更新器优化的是未来窗口效用，同时受旧能力、延迟和状态大小约束。若一个方法只提高当前标签拟合，却没有改善 `J_Q` 或恢复时间，就不能称为有效的实时训练方法。

## 8. 与 backbone 选择的关系

backbone `E_φ` 只负责产生 `H_t(c)`；更新算子 `U_ψ` 负责把延迟事件转成状态变化。先固定上述数学合约，再在同一事件流上比较候选 encoder；不能因为某个模型已经有现成训练脚本，就反过来改变问题定义。

本定义把每次选择先视为 contextual bandit：动作不会直接改变下一步的潜在结果分布，除非这种影响已经通过后续上下文和候选集合体现出来。若 peer 协作会改变系统状态并持续影响未来任务，则应把 `X_t` 扩展为受动作控制的环境状态，升级为 delayed-feedback controlled Markov process；不能在 bandit 公式下偷偷声称已经解决了长期协作。
