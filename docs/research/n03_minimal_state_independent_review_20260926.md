# N03 独立审查：先让角色证据有对象

日期：2026-09-26。状态：**独立设计审查，供主执行者采纳或反驳；不是方法冻结、预注册或实验结果。**

**结论：当前 fresh-call 协议可以检验交付判断，但缺少可延续的 peer 差异来源，不宜直接扩大为角色学习实验。** 最小修正是让同一起点的 agent 保留自己实际参与产生的经验，同时把“我怎样做事”与“别人评价某个 peer 怎样做事”分开；这只使研究命题可检验，不保证记忆有用、角色出现或方法创新成立。

本次只读取已有记录并写本报告，没有新 API 调用、候选代码运行或 GPU 实验，没有改写历史评分。采用 `my-doc` 的调研与公式规范；所有带数字的演示均标为示意，不作实测证据。

## 证据：N02 暴露三个缺口

下列事实来自 [v3 独立审查](../../experiments/logs/n02_peerrole_dev_v3_20260926/independent_review.json)、[冻结配置](../../experiments/logs/n02_peerrole_dev_v3_20260926/config.json)和 [N00–N05 台账](../coordination/AAMAS_TASKS.md)。后验诊断与 v3 原始分数分开，不能回填成当时可见标签。

| 已核事实 | 能说明什么 | 不能说明什么 |
|---|---|---|
| v3 两个同结构实例、六次真实调用完成；consumer 都为 4/4 | 限定消费链和列出的四项行为检查完成 | 完整 DIST1 正确率、角色学习或跨 root 泛化 |
| 两次都宣称 repair，但只改 `consumer.py` | 接收者完成了自己的接口适配 | 生产者造成的返工或其边际成本 |

| 两次 repair 被固定映射为 0.5，原分值也是 0.5 | 更新程序执行但数值未变 | 有概率变化、选择收益或需要事后调整映射 |

[责任诊断](../../experiments/logs/n02_posthoc_responsibility_20260926/summary.json)和 [priority 诊断](../../experiments/logs/n02_posthoc_priority_sandbox_20260926/summary.json)支持上表第二、三行。原来的 `4/4` 对声明的四项检查仍然成立，完整合同存在缺陷的后验发现应另记，不能覆盖原分数。

还有一项 benchmark 边界：已执行 consumer 使用 queue，没有使用 priority。补上 priority 检查能覆盖生产者合同，却不能把该模块的正确率自动解释为下游消费效用；合同应逐项标注“交付义务”与“当前消费路径依赖”。

## 可识别性：身份不能凭空带来能力

这里的第一性需求是：**过去关于某个 peer 的证据，必须能预测这个 peer 未来的工作，才值得按 peer 学习。** ID 是索引，不能自己产生持续能力。

沿用现有模型中的任务 $x_t$、被选 producer $a_t$、实际接收者 $j_t$、交付 $o_t$ 和已到达合法历史 $\mathcal F_t$。任务包含公开需求与权限；接收者由预先声明的分配器给定，不能看完结果才选择。

### 条件命题：可交换调用没有身份增益

假设给定当前任务和合法历史，所有可选 peer 使用相同执行核，没有由身份绑定的历史、模型、工具状态、缓存或持续随机效应。此时对任意一类交付 $D$：

$$
\Pr(o_t\in D\mid x_t,\mathcal F_t,a_t=a)
=K_t(D\mid x_t,\mathcal F_t),\qquad \text{对所有可选 }a.
$$

**Case：** `x_t` 是同一份 DIST1 公开源码和 queue/priority 写权限；选择 A 或 B 后送给 API 的请求字节与模型配置完全相同，且没有按 A/B 绑定的会话或记忆。$D$ 可以是“priority 模块能够导入”的源码集合，$K_t$ 是该时刻 API 对这份请求产生源码的分布，并不要求两次抽样产生相同文本。

再令 $g_x(o)$ 是不读取 peer 名字的独立交付检查，输出 $[0,1]$ 内预先定义的分数；检查不完整时不给这个标量。由相同分布立即得到：

$$
\mathbb E[g_{x_t}(o_t)\mid x_t,\mathcal F_t,a_t=a]
=\mathbb E[g_{x_t}(o_t)\mid x_t,\mathcal F_t,a_t=b].
$$

**Case：** 对同一任务，独立检查只看交付源码是否符合公开构造接口，不看“作者是 A 还是 B”。在上式假设下，A 上次碰巧正确不能使 A 下次的该检查通过率高于 B；若二者的真实条件通过率都为 0.6，任何按历史 ID 挑选的策略当步期望仍是 0.6。这个 0.6 是示意值，不是本项目测量。

**可证明部分：** 第一式假设成立时，第二式是对同一个分布求期望；再对选择概率加权，任何 peer 策略的当步期望交付分相同。有限样本的“B 最近较好”仍可能出现，但没有因此建立稳定的 B 特性。

**必须核验部分：** 相同模型名称不证明第一式。身份若绑定私有工具、session、记忆、负载或不同执行环境，假设会失败；按时间选择不同 ID 也可能把 API 漂移错认成身份效应。

### 反例：终局差异未必来自生产者

上面只证明身份对独立交付质量没有增量，不自动覆盖团队终局。当前 recipient 能看到生产者身份和他人评价；若它因此多检查、多修复或轻信某人，终局可能按 ID 不同，尽管生产者完全可交换。

因此应分别问：证据是否预测原交付、是否预测某接收者的整合结果、是否改变接收者投入。仅在第三项发生变化时，可研究信任与努力分配，但不能称已经学到生产者专长。

## 最小状态：经历与声誉分开

**只需为现有模型增加一种实际存在的状态：每个 agent 自己保留的经历。** 无须默认引入隐藏专长向量、图神经网络、专家标签或完整 POMDP 求解器。

| 对象 | 内容与拥有者 | 可见性与用途 |
|---|---|---|
| $m_{a,t}$：自己的工作经历 | a 真正参与的任务、自己提交的产物、已合法收到的反馈及其来源 | a 用来执行下一次任务；原始私有内容不默认给 selector |
| $s_{j,t}$：关于 peer 的证据 | j 合法收到的“谁评谁、评了哪份交付、什么情境、依据是什么” | j 的 selector 用来分配未来职责；可含其他真实接收者的见证 |
| 当前任务与合同 | 公开输入、producer 义务、consumer 义务、合法邻居 | 所有条件同规则获得，不含隐藏测试或将来结果 |

同一个 agent 可以既做 producer 又做 consumer。它作为 consumer 实际读过代码、做过接口适配，这也是自己的工作经历；但“听 A 说 B 不可靠”属于 about-peer evidence，不能伪装成自己执行过 B 的任务。

### 同起点不等于永远无状态

$$
m_{a,1}=\varnothing,\qquad s_{a,1}=\varnothing
\quad\text{对每个 agent }a.
$$

**Case：** A、B、C 都用相同模型、权限、token 与工具额度；开始时都没有案例笔记或信誉分。首次选中 B 只是预先固定随机探索的结果，不是给 B 指派“队列专家”。

执行端加入自己的经验后：

$$
o_t\sim K(\,\cdot\mid x_t,m_{a_t,t}).
$$

**Case：** B 后来执行一个新交付任务时，请求中除了当前公开任务，还包含 B 上次真实交付的有界经验记录；A 若没有这次经历，就没有该记录。记录可以写“consumer A 报告采用 ack/nack 后继续整合，报告尚未证明全部 producer 模块正确”，不能写研究者事后才发现的 priority 检查结果。

这提供了未来质量差异的**可能来源**，不是证明差异已经存在。模型可能忽略经验、被错误经验误导，或者所有人仍同样成功；“状态内容不同”不是资格通过标准。

### 用同一规则保留实际经历

最小工程建议是确定性的有界经验包：从本人实际参与记录中按时间选取，并以固定 token 上限截取，不增加总结模型、不先引入可训练记忆网络。以下仅写机制，保留条数、token 上限和字段裁剪顺序必须在新卡中冻结。

$$
m_{a,t+1}=
\begin{cases}
\operatorname{Keep}_{L}(m_{a,t}\mathbin\Vert \ell_{a,t}),
&\text{本轮有 a 的新合法经历到达},\\
m_{a,t},&\text{否则}.
\end{cases}
$$

**Case：** $\ell_{B,t}$ 是 B 的本次 queue/priority 交付、来源哈希和被允许返回给 B 的接收记录；$\ell_{A,t}$ 是 A 自己实施 consumer 适配的记录。C 未参与且未获授权读取该工作内容，就不获得这两份私有经历；$\operatorname{Keep}_{L}$ 是同一固定截取程序，$L$ 是每人的记忆 token 预算。

日志保存完整经历，模型只读冻结规则选出的片段；保存哈希不等于向模型提供了内容。允许存储自己的代码或修改片段时，应明确这是一种经验复用，重复 root 上的收益可能只是解法复用，不能据此称跨任务角色泛化。

实现不必直接把 agent ID 当自然语言人格喂给模型。ID 用于正确载入本人状态即可；关键是请求绑定了实际记忆哈希，而不是请求里写了一句“你是 B”。

### 见证更新的是被评价对象

$$
s_{j,t+1}=U(s_{j,t},\mathcal B_{j,t}),\qquad
a_t\sim\pi(\,\cdot\mid x_t,C_t,s_{j_t,t}).
$$

**Case：** $\mathcal B_{C,t}$ 是已经到达、允许传给 C 的“A 评价 B 的交付”记录，其中包含 A、B、任务语境和原交付哈希。C 可以据此调整下次委派给 B 的概率；它不能据此给 A 的 producer 能力加分，也不能拿尚未执行的候选交付作选择依据。

这里 $C_t$ 仍是合法候选集合，$U$ 与 $\pi$ 暂不锁定算法。给第三方 C 一条已授权见证，无须把 B 的私有代码经验全量公开，更无须把所有 agent 的记忆同步成一样。

**关键防混淆：** 一条反馈可以合法地同时影响 B 的执行经验和 C 关于 B 的估计，但这两条路径必须分别记账。若选择器所有条件都共用相同经验更新规则，后续才能比较见证选择机制；否则收益可能只是某组的 producer 多获得了改进提示。

N03 的最小建议是先让见证进入未来分配器，不直接拼接到本轮新判断的提示里；新判断基于本次交付、职责合同与接收者本人的合法执行经验。若另行研究“先看声誉再审交付”，应登记为单独的信息通道，并检查评价相互抄写；只把旧评价转述一遍不能算新增独立证据。

接收者自己的经验也须进入其判断与实施请求，并绑定同一份读取快照。不能只让 producer 有记忆、却把 consumer 当无状态裁判，同时声称完整团队的持续工作方式已被建模。

## 责任：动作名不能当正确性

**先说明谁负责什么，再测量实际交付、实际使用和成本。** 当前 `repair` 既覆盖自身适配又被拿作 producer 分值，导致标签目标不清；不能靠把 0.5 改成别的数解决。

前瞻性合同至少向双方展示 producer-owned paths、consumer-owned paths 与逐项义务。目录权限只证明允许改哪里，公开接口合同才判断谁应该完成哪项行为。

$$
\text{观察到的上游修改}
=\text{实际改动路径}\cap\text{producer 负责路径}.
$$

**Case：** v3 的实际改动为 `{mqueue/consumer.py}`，producer 路径为 `{mqueue/queue.py, mqueue/priority.py}`，交集为空。它只证明没有修改 producer 文件；不能推出 producer 正确、没有替代性绕过，或接收者没有因上游问题多花时间。

对当前任务，应分开保存以下观测，不急于合成一个奖励：

| 观测 | 可接受定义 | 不可替代的内容 |
|---|---|---|
| 原交付质量 | 消费者改动前，对生产者合同作版本化独立检查；未覆盖项明列 | 消费后通过率不能反推它 |
| 预使用判断 | 具体义务、问题路径、证据、UNKNOWN 选项与判断时间 | 自信度不等于正确性 |
| 实际消费行为 | 使用了哪些接口、改了哪些上游与自身文件、执行发生了什么 | 宣称 `repair` 不证明发生上游修复 |
| 消费后质量 | 在封存最终产物上运行预先声明检查 | 不自动代表原生完整 benchmark 分数 |
| 完整成本 | producer、判断、consumer、工具、通信与更新分别计时计 token | 全部 consumer 用时不是 peer 造成的边际返工 |

当前 pre-action judgment 来自源码审查，不能写成已经经历运行反馈的判断。若未来要让接收者报告运行中问题，须真的给它合法执行观察并计入调用/工具预算；不能把父评分器结果冒充接收者亲历。

$$
\text{仅有完整 consumer 调用成本}
\quad\not\Rightarrow\quad
\text{已识别上游造成的边际返工成本}.
$$

**Case：** 即使 B 的 queue 完全正确，A 仍需实现自己负责的 `consumer.py`。没有一个可比的正确上游参照或其他明确识别设计时，A 用时 10 秒只能记为实际整合用时，不能记为 B 导致了 10 秒返工；10 秒是示意值。

独立 producer 检查应该覆盖其承诺接口，包括导入和原构造方式；但仅补这两项还不足以证明完整并发正确性。对 priority 这类当前消费路径未使用的模块，分报合同正确性，并保留“对当前接收者效用未测”的标记。

若保留完整 DIST1，继续覆盖其原义务；若另做仅 queue→consumer 的最小交接诊断，必须作为新范围前瞻性登记，明确它不是完整原生 DIST1。不能观察到 priority 出错后静默把它删除来提高分数。

## 数据边界：经历不能穿越测试集

**selected-only 的意思是只有实际被选且执行的 producer 才产生这次 producer 证据。** 同一次协作也能为实际接收者形成自己的工作经历，但未执行候选没有这次能力标签。

$$
g_t=g_{x_t}(o_t),\qquad o_t\text{ 只由 }a_t\text{ 实际生成}.
$$

**Case：** 本次选择 B，只有 B 的实际交付能得到本次 producer 检查；不能顺便生成 A/C 的产物再隐藏、把它们作为学习标签。若独立审计分没有被前瞻性声明为在线可用，它只进入离线分析，不能写进 B 的记忆或 C 的选择状态。

任何延迟反馈先按来源绑定当时的交付与状态版本，再在到达后用于未来任务。B 中途经验改变不意味着旧反馈作废，也不意味着旧反馈是在评价 B 的新状态；证据应保留经历时点/曝光量，测试旧评价是否还能预测新状态。

任务独立性按结构来源分组，不按 seed 或文本哈希分组：

$$
\operatorname{Root}(\text{开发任务})
\cap
\operatorname{Root}(\text{独立确认任务})
=\varnothing.
$$

**Case：** 当前 DIST1 seed 0 和 seed 1 都来自同一生成器结构，改了类名也不能分到开发与独立确认两边。确认任务若来自此前没看过的独立代码与故障结构，可以携带开发期合法学到的经验，但不得携带该确认 root 的旧解答或评分。

必须区分两种评估：首次遇到未见 root 时的转移能力，以及在同一 root 内获得反馈后的适应能力。后者允许当流反馈继续更新，却不能把后续 sibling 重新称为独立 holdout。

防泄漏记录至少绑定任务 root、产物来源、记忆读取清单与哈希、见证权限、到达时间和实际选择概率。当前两个完整 N02 episode 仍只做同 root 接入证据，新合同下不兼容的样本不补跑、不混成新训练数据。

## 对照：相同信息也要相同经历机制

**新记忆机制必须是所有主要选择器共同的执行环境，不能只给候选方法。** 各方法拥有独立 live 历史；所谓公平是信息权限、初态、预算、更新规则和任务机会相同，不是强行让不同选择结果得到相同的后续经历。

| 条件 | selector 获得的证据 | 主要回答的问题 |
|---|---|---|
| 随机/不更新 | 当前公开任务、候选；不据反馈更新选择 | 选择学习是否产生额外价值 |
| 终局-only 上下文选择器 | 当前任务、历史实际选中者终局、完整成本 | situated evidence 是否比稀疏终局更有用 |
| 同信息 contextual trust/bandit | 与候选方法相同的原始合法见证、语境、来源、时间及成本 | 新更新方式是否超出现成选择估计 |
| 待定候选方法 | 同上，只有更新/表示机制发生预声明变化 | 真正的方法差异是否有收益 |

优先复用现有事件账本、版本/延迟接口和已审查的简单在线估计实现；先以可解释的总体信誉和上下文交互作诊断。RLS/online SGD/周期拟合的引入，应服务于明确的预测或更新瓶颈，不因“已有代码”自动升级为论文创新。

同信息强基线不能只得到 `accept/repair/reject` 三分类，而候选方法独享具体错误文本和 source lineage；也不能不给它实际接收者 ID/任务情境。若输入经过压缩，先给双方相同压缩结果，或单列表示能力实验。

$$
\pi_{\mathrm{baseline}}(\cdot\mid x_t,C_t,s_t)
=\pi_{\mathrm{candidate}}(\cdot\mid x_t,C_t,s_t)
\quad\Longrightarrow\quad
\text{同候选顺序、同采样器和同随机数下选择相同}.
$$

**Case：** 若候选只是把关于 B 的评分做指数移动平均，再 softmax；强基线使用完全相同的合法事件、更新、候选排列和随机数到候选的映射，就会逐步复现所有选择。仅有相同概率分布并不够：候选顺序颠倒时，同一个随机数可能抽到另一人；将这个表叫“角色库”不会产生新算法，这是已有 [最小算子审查](../scientist/analysis/AAMAS_ORIGINAL_Q1_OPERATOR_CANDIDATE_20260923.md)指出的边界。

N03 应继续采用固定覆盖的随机探索，先问“证据能否预测未来”，而非同时改学员记忆、selector 算法和拓扑。三个 agent 的完全图只足以做最小第三方见证链，不能支撑稀疏网络、探索新边或规模涌现结论。

## 控制过程：一次日志不能证明长期策略

**记忆会受选择影响，之后的候选能力也会改变。** 这正是长期角色学习有意义的地方，也意味着不能把同一条日志影子回放成多种真实团队历史。

$$
t^+=\min\{k>t:a_k=a_t\},\qquad
o_{t^+}\sim K(\,\cdot\mid x_{t^+},m_{a_t,t^+}).
$$

**Case：** 本轮委派给 B；下轮若选 A，B 的新经验不直接成为 A 的 producer 输入。$t^+$ 只指此后 B 再次被选的第一次时点；若存在该时点，且本轮经验仍保留在 B 的 $m_{B,t^+}$ 中，它才可能影响 B 的后续生成。若 B 此后未被选，$t^+$ 不存在，不声称观察到此条经验的后效；该索引用于分析，不是选择器提前知道的未来信息。

在另一策略本轮委派 A 的轨迹中，后续 A/B 状态会沿不同经历发展。把原日志中 B 的未来产物复制给另一策略，不是该策略真实会生成的结果；经验是否实际改变分布仍需测量。

一轮信号诊断可以在已有合法历史上预测下一份选中交付；contextual bandit 仍是合理的单步强基线。完整长期策略收益必须保留各条件独立轨迹；简单逐事件 IPS 不能自动估计选择改变学习状态后的长期回报，不能用 OPE 数字替代 live 对照。

同样，打乱 witness 来源是诊断控制，不是可执行的新历史。小样本若在相同 root、时间、接收者和曝光阶段内没有可比记录，就应写“该负对照不可识别”，不能随意全局打乱制造显著差异。

## 判决：先过六个前置门

**准许继续无 API 的合同/测量修复；不建议立即新增学习信号调用或 A800 训练。** N02 四次尝试预算已耗尽，后续另立 N03 卡，开发总上限 24 次仍包括这四次，剩余额度不是必须花满的配额。

以下顺序每一步都回答一个独立问题；通过表示下一步值得尝试，不表示最终方法成立。

1. **责任门。** 双方请求明确同一份 ownership/obligation map；源码判断能标出问题属于 producer、自身整合或 UNKNOWN。用 v3 现有产物核对分类，不修改旧判断。
2. **测量门。** 每项 producer 义务对应已测或明确未测结果；独立交付与消费后质量分开。保留正确控制和已发现的 priority 缺陷，不能把通过 consumer 四项等同完整任务成功。
3. **状态门。** 同初态、统一有界经验更新；只有实际经历进入本人请求，见证只更新所指 peer。静态检查和无调用夹具先验证读取清单、时间、权限与哈希，不能把夹具当记忆有效证据。
4. **任务门。** 预先列出结构 root、可重复职责语境、合法第三方接收者和完整成本；只有一类 queue root 时，只能登记局部适配诊断，不能登记角色分工确认实验。
5. **信号门。** 前瞻性比较无历史、总体 peer 历史、任务/接收者语境、带来源的真实判断，对随后选中产物的预测；保留 UNKNOWN 与失败，报告不确定性。20 次以内的新尝试只提供探索线索，不能合理拟合大量 peer×任务×接收者参数后宣称发现规律。
6. **增量门。** 只有信号存在且强同信息基线留下明确瓶颈，才冻结一个新机制并进入训练验证；若普通上下文估计已吸收全部信号，不用复杂 backbone 掩盖这一结果。

### 停止与反例：不能为了信号造专家

| 反例或观察 | 合理解释与处置 |
|---|---|
| 记忆不同但未来质量/成本没有可检测关联 | 先分清样本不足、任务饱和、记忆无效；不宣布不可能，也不盲目扩量 |
| 所有 agent 同样高分或同样失败 | 当前任务/模型组合缺少诊断范围；按新合同选择一个更适配基底，不能事后降预算造失败 |
| 只靠某个 peer 总体均值就能预测 | 可能是一般信誉，不足以支持 situated role 分化 |
| 同 root 复用旧代码有效，未见 root 无证据 | 经验复用成立与否另报；不称可迁移角色 |
| B 的评价变差来自 A 不会整合或身份偏见 | 记录接收者与交互，不能都归到 B 的能力 |
| 只有被研究者预设“专家”的身份有效 | 实验对象被替换，不能支持同起点自然形成分工 |
| 学得越快，旧见证越快过期 | 需要版本/时效建模的实测依据；不是直接上更复杂网络的理由 |
| 更好质量被评价、记忆、通信的总成本抵消 | 无实际协作收益；应保留该负结果 |
| 同信息现成算法逐步复现候选 | 没有新选择算法贡献，停止以该实现申请昂贵确认 |

“记忆不改变执行分布”可由反例推翻整个当前实现路线；“小样本暂未看到差异”则只能判不确定。N03 需要预先写区分规则，不能看完结果再选择更有利的解释。

## 可复用内容：不重造运行框架

现在能直接复用的是：真实 SSE 调用封存、执行前 selection/propensity、交付哈希与不可变产物、按权限消费副本、已有 sandbox 边界、父进程 consumer 检查、责任路径分类，以及两个真实 priority 缺陷作评分覆盖回归样本。新的工作应集中在经验状态接入、义务可见性和缺失测量，不重复搭 API/GPU 框架。

[Stream-JEV v2](streamjev_method_spec_v2.md)仍是工程 baseline 规格；它的在线参数状态和本报告的 agent 工作经验不是同一对象。其文内“第一版使用 Laya”不能凌驾于页首与 [创新边界](streamjev_novelty_boundary_20260925.md)的未冻结状态，本审查不选择 Laya、AnyJev、RLS 或任何最终训练算法。

**最终判断：** 有一个可以小步实现、可以被反驳的最小方向，但尚无已证明有效的训练方案。修正后的故事应当是“实际经历使 peer 的工作方式有可能持续变化，实际接收者的可归属判断帮助别人识别这种变化，再改善后续职责分配”；每个箭头都要分别接受实验，而不是用一个新模型名把缺失证据补起来。
