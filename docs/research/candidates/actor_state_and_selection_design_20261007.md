# 让个人经验与选人收益各自可检验

日期：2026-10-07。状态：`CANDIDATE / NOT_RUN`。不替代六份生效文档，不改变 Goal，
不授权新 API。当前待确认的四次 PIPE3 判断预算不包含本卡。

**核心问题：让同一个 peer 真正带着自己的经历做下一次任务，再检查别人对它的评价
是否帮助选人。个人变强与选人变好必须分别测量。** 这里的个人记忆是实验环境的一部分，
不充当 ER-G2 所要求的新在线训练机制，也不证明任何新颖性。

## 1. 代码已实现什么，缺什么

| 现有资产 | 可复用内容 | 实际缺口 |
|---|---|---|
| `ActorExperience` | stream/arm/actor 隔离、历史截断、决策快照、重复幂等 | 没有 production caller；没有进入真实请求；字段黑名单不能证明文本无私有内容 |
| serial `real_closed_loop` | 实际 producer 请求、解析、保存响应；未来可再次选同一 peer | 使用未版本化身份，没有个人经验输入；旧实验材料及评分不能直接当新卡 |
| C1 bounded live | 版本身份、ledger、真实 recipient 判断/动作 | 两个 producer 是静态文件；交付直接复用，不能检验 producer 自身学习 |
| native `Delivery` | 候选源码摘要与本次产物摘要分别存在 | C1 与 two-stage composition 额外强制两者相同；不是 native protocol 的必然要求 |

独立只读调用链审查没有发现 `ActorExperience` 的生产导入。原来的四项测试只检查
历史容器，不能说明真实 actor 已经有记忆。本卡不重跑这些测试来冒充研究进展。

## 2. 从需求选机制，不从已有框架选故事

未来的同一 peer 必须有可追溯的持续状态，否则同模型、同输入、无状态的新调用只因
ID 不同就产生可预测能力差异没有依据。合法经历可以提供持续状态，但也可能固化
错误，不能预设它一定有益。

| 路径 | 问题 | 本轮取舍 |
|---|---|---|
| 个人历史输入，固定分派规则 | 经历是否改变自己下一次真实执行？ | 作为环境信号检查；不叫 selector 收益 |
| 冻结个人历史，比较选择器 | 面对同一群 peer，评价是否改善后续分派？ | 主张最直接的局部检验；仍要强同信息基线 |
| 个人经验与分派共同持续变化 | 角色是否在协作中形成，系统是否稳定适应？ | 最终独立 live histories 要验证；前两项不能替代它 |

推荐最小实现是先复用有界原始交互，不增加 reflection 模型调用。它只是一个可检验的
环境选择。若不足，不能把它的失败解释为“所有自进化不可行”；需明确瓶颈再比较
合法反馈反思、技能记忆等替代，不能偷偷追加一层并沿用旧实验名。

[Reflexion 原论文](https://arxiv.org/abs/2303.11366v4)把试错反馈转成语言反思并用于以后
尝试，参数不随该过程更新。固定源码的 HotPotQA 路径含上次轨迹/反思提示，编程路径
则用执行反馈引导下一次修订。这提供可复用范式，但不证明跨任务 peer 选择有效。
本卡不接入其 evaluator 或照搬反馈权限；只采用“历史进入后续输入”的已有思路。
[源码与 MIT 许可](../../../references/aamas/reflexion_memory_origin_20261007/manifest.json)
已保存，没有执行外部代码，也没有复现其论文效果。

## 3. 身份、经历和本次产物不要合成一个版本

**候选版本固定“怎么生成”，经历记录“此前做过什么”，产物记录“这次生成了什么”。**

| 已有字段/对象 | 下一 runner 的明确含义 | 变化时怎么处理 |
|---|---|---|
| `candidate_id@version`、`source_digest`、`model_config_digest` | 固定生成代码、模板、记忆规则与模型配置 | 配置改变才开新版本；所有 peer 初态相同，不能预设专家 |
| `ActorExperience.snapshot().state_digest` | 这次请求之前、属于这个 peer 的已完成经历 | 每次封存；自然经历增加不重命名 peer；旧快照不可覆盖 |
| `Delivery.artifact_sha256` | 本次实际模型新生成的交付 | 每次单独记录，不要求等于策略源码摘要 |

不能把 C1 原有 `source_digest` 的静态文件语义原地改掉：新 runner/card 明示候选类型，
旧卡、旧检查与回执保留。只允许生成策略相同的 peer 自然积累不同经历，不人工挑
一个历史好产物给 B、坏产物给 C 再称自然能力形成。

复用 `peerrolebench_pipe3_two_stage_composition.py` 时也必须处理其297–326行的
静态等值闸口，不能只改 C1 就宣称接通。现有 observation/bridge 将 registry 摘要
绑定 `candidate_source_digest`，把 Qp/J/action 另绑定实际 artifact；这个区分可直接
复用。新策略摘要的声明、实际执行模板和 history 快照仍需 runner 在调用前绑定，
一个用户传入的 `source_digest_match=true` 不构成执行证明。

历史参与 prompt 时采用当前公开任务与自身既往输入/输出的投影。request ID、耗时、
token 等 operator 元数据照常保存，最小方案不把它们喂给 actor。当前任务对象不能
包含序列化的旧历史再写回记忆，否则“历史里套历史”，容量与公平性会失真。完整
实际请求单独保存，记忆只保存该次基础任务和自身答复；不做静默 token 截断。

## 4. 一条可审计的执行路径

```text
同初始模型、模板、容量、空历史；随机化自然源任务的分配
→ producer 只读取自己的合法旧经历并真正调用模型
→ recipient 实际接收、判断、行动；独立测 Qp、adoption、Y、成本
→ producer 记录自己原本可见的基础任务和自己的答复；不写入私有测评分数
→ 按方案 B 发布有类型的 J；历史和 read cut 封存
→ selector 在执行前选人；assignment、概率和输入快照封存
→ 被选 peer 生成新的交付，recipient 真正执行
→ 独立后续收益合法且完整才更新 selector
→ 再次执行未来任务，才有资格检验更新的作用
```

这是流程合同，不是本轮已执行轨迹。若给 producer 回传消费方 J，需要另明确反馈
到达与可见边界；本卡最小版本只给它自己的原始交互，J 作为 selector 的观察。
由此得到的无收益只能限制这个版本，不能推及有反馈反思的所有 actor。

| 谁读取 | 可以读取 | 不得从本卡路径得到 |
|---|---|---|
| producer | 本任务合法输入、自己的既往基础输入/答复 | scorer、Qp/Y、他人完整经历、selector 参数、当前/未来结果 |
| recipient | 本任务规范、实际交付、按任务合同合法可见信息 | producer 私有历史、隐藏标签和未来结果 |
| selector 与同信息对照 | 当前上下文、合法菜单、已发布的同一观察快照 | 任意 peer 的私有 prompt、未选 target 结果、私有 scorer |
| operator | 完整溯源、独立评分与成本 | 不得把 operator 字段回流给 actor/selector |

Planner 的原生 spec 属于该 Planner 的合法输入，不是全局公开信息；“只存自己的
合法输入”不表示其他 actor 也能读该记录。存储路径与请求投影均按身份隔离。

## 5. 最小判别设计：先隔离状态，再谈闭环增益

先行诊断从真实源经历的同一截止点产生隔离克隆，目标任务及接收方策略固定。两个
peer 各做一次“读自己的历史”和“遮蔽历史”的 **fresh** 目标执行。这是四条路由，
不是四次 API；若每路由要 producer、judgment、action，则仅目标部分就需12次调用，
尚未包含源任务、Verifier 或反思。不能复用待批准的四次判断预算偷跑。

事前封存候选方法、同信息 contextual baseline 及 J-masked/count 对照的概率向量。
四条完整路由及其原始质量/成本仅进入 **operator 诊断账**，用于检查 peer 差异是否
自然存在、是否与评价方向一致。这不是四次 selected-only 训练，未选结果不能进入
线上策略或个人经验。额外调用计研发总成本，不伪装成部署时只执行一人的成本。

这只是小样本诊断；目标任务不是已知源任务的重跑，更不能按源分数挑目标。四条路由
只给出这个 source 截止点和 target 的实际收益；**不能给下表的总体 μ 赋值、计算其
置信区间或声称交互成立**。即使预封存两套策略概率，也只可作同一固定样本的诊断性
加权，且需要产物生成不受被选策略身份影响，不能替代独立 live 实验。

PIPE1 Planner 的旧合法规则可能与新任务相同。源/目标卡必须事前声明 exact-instance、
字段/转换规则、业务域与 structural root 的重叠层次。合法旧规则复用不是泄漏，
但同规则换数据不能支持新规则或跨 root 泛化。当前/未来 expected、答案产物与
私有 scorer 不得进入源历史；规则/样本的 hash 与交集必须在调用前审计。

### 未来 online 四格（未运行，与上面的四条诊断路由不同）

正式矩阵仍需独立 stream、两个 structural roots、未见任务与强基线闭环比较。
可把系统制度的四格定义为：

| 个人历史输入 | 同信息强 contextual 对照 | 候选选择器 |
|---|---|---|
| 遮蔽 | μ00 | μ01 |
| 可见 | μ10 | μ11 |

μms 是预注册任务流分布下的平均完整质量–成本收益；m 是历史输入开关，s 是 selector
的对照/候选开关，都是预先干预条件，不是新增环境原始输入。不同制度会产生不同
真实交付和 J，不能声称其 realized histories 相同；公平性是同一生成/发布规则、
信息权限、初始化、任务分布和预算。固定快照诊断中各比较器才读取字节相同的 J。
“无 J”是另外的信息消融，不能冒充强同信息对照。

$$
\mu_{11}-\mu_{00}=(\mu_{10}-\mu_{00})+(\mu_{01}-\mu_{00})
+(\mu_{11}-\mu_{10}-\mu_{01}+\mu_{00}).
$$

Case：μ10−μ00 是对照选择器下打开个人历史的**系统总效应**，其中可能包含
“个人输出变化→J变化→contextual改变分派”的间接路径；不能叫纯 actor 能力收益。
μ01−μ00 是遮蔽历史时更换 selector 的制度增量；最后一项是制度交互。它们是
总体均值上的恒等分解，尚无实测值，不做路径归因。若要单测 actor 输入的局部作用，
使用前述固定源/J与固定分派的 target 诊断；若要谈长期角色形成，仍需独立 live 流。

## 6. 什么结果会改变下一步

- 没有 fresh producer 调用、没有合法持续身份、隐藏标签泄漏、无独立目标/成本、
  或历史无法影响实际请求：停止该执行卡并修实现，不能靠扩大样本解决。
- 历史改变输出但未改善效用：记录该记忆机制的限制，不把文本差异当能力增长。
- J 差异可能只是源任务抽样噪声；如果未来效用仍不可预测，保留不确定性，不能
  靠固定好坏产物或预设专家强行制造信号。
- 小 pilot 看不出 actor-only 或 selector-only 收益，记 `INCONCLUSIVE`。不排除
  二者交互；统计性否定需要预注册的实际等效界、精度和足量独立流。
- 候选方法与 contextual 同样有效，不支持专属优势；基线也变好可以支持任务的
  可学习性，但不能替代我们的增量创新要求。

## 7. 复用顺序与尚未冻结项

优先复用 `ActorExperience`、native registry/Delivery、真实 API transport、已测的
独立 scorer 和成本日志。新增 runner 只接通稳定生成身份、历史投影、fresh delivery
及封存边界；不为此再写一套通用记忆/反思框架，不改旧 C1。

PIPE1 的 relay/Verifier/TZ/评分覆盖、源–目标 split、容量/token 上限、具体模型、
成本权重、独立流数及追加预算尚未冻结，因此本卡 **不可执行**。下一步先完成这些
会改变结论的条件，再冻结执行卡。个人经验基座在所有正式 arms 中相同，不能把它
只给候选方法；新的 selector 训练贡献和 A800 准入条件均保持原要求。
